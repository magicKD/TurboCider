# Qwen Image 2.1: 512px edit references and sequence-tiled first-step FFN

The production 512² edit with 1–3 references still defaults to the existing
GPU-only route. The explicit `qwen21_reference_size=512` option resizes each
reference to **512px before VAE encoding**, requires `allow_approximation`,
and is not the same input as the normal 1024px-reference edit. This screen
compares **identical resized inputs** across GPU and checkpoint-matched W8A8
GPU/Core ML. The W8A8 route offloads only the 1024-row output-image decode
FFN after the exact GPU first step, using a 6144/12288-channel partition and
all 32 layers. The `cpuAndNeuralEngine` Core ML policy does **not** establish
physical ANE residency.

M4 Max, Comfy BF16 checkpoint, resident Session with separate prepare and
two-step warmup, cached prompt/references, 512² PNG output, seed 42 for the
one-reference red-teapot edit and seed 17 for the ordered two-/three-object
edits. All arms dump equal text, initial noise and ordered reference latents;
the comparison verifier checked their payloads, not just metadata. Wall is
the warm request **including VAE, export and dumps**, not model load. Times
below are individual runs, not a broad quality or device-placement claim.

| References (512px each) | First-step rows incl. text/target | 5-step GPU | Decode-only W8A8 | Same-input speedup |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 2091 | 7.256 s | 6.031 s | 1.203× |
| 2 | 3157 | 8.675 s | 7.389 s | 1.174× |
| 3 | 4226 | 10.114 s | 8.898 s | 1.137× |
| 3, 40 steps | 4226 | 52.327 s | 39.535 s | 1.324× |

The 1-/2-/3-reference decode-only route makes respectively 128 W8A8 calls
per 5-step request (32 per decode step). At 40 steps it makes 1248. No Core
ML output copies or runtime failures were reported. The one-reference edit
retains the pot/lid/spout/handle and becomes reddish but **fails the requested
matte finish in both GPU and W8A8 outputs**. The two-reference comparison
preserves both pots with minor differences in the transparent blue pot. The
three-reference five-/40-step outputs retain both pots and the recognizable
central dragon sticker; neither pixel correlation nor this one prompt proves
general reference fidelity.

For the first step, an explicit **diagnostic only** implementation loops over
1024-row pieces of each post-attention FFN input, pads/trims the last piece,
and feeds the same calibrated Core ML layer repeatedly. Attention geometry,
reference ordering and prefix KV remain untouched. It materializes an
independent result for every prediction before Core ML can reuse the shared
output backing. `TURBOCIDER_QWEN21_TILED_PREFILL_W8A8_DIAGNOSTIC=1` applies
this to all 32 first-step layers; `=8`, `=16`, `=20`, or `=24` applies it to
only the last 8, 16, 20, or 24 layers, leaving the preceding FFNs exact BF16 GPU.
All modes require explicit W8A8,
6144-channel 32-layer manifest, 512² output, 1–3 resized-512 references,
approximation opt-in, and no LoRA; unset/`0` changes nothing. The model
geometry is checked at runtime. These diagnostics now explicitly reject
cross-request prefix-KV reuse: on a hit no full-sequence first step is
executed, so tiled-first-step prediction-count assumptions do not hold.
That restriction describes the original screen; the later explicitly gated
last-16 resident experiment is documented in
[the tiled-prefix follow-up](qwen21-tiled-prefix-kv-edit-2026-09-27.md).
None of these modes is a recommended CLI preset.

| Same-input arm | 3-ref 5-step wall | vs decode-only | 3-ref 40-step wall | vs decode-only | Extra first-step Core ML calls |
| --- | ---: | ---: | ---: | ---: | ---: |
| Decode-only W8A8 | 8.898 s | — | 39.535 s | — | 0 |
| All 32 layers tiled | 7.946 s | 1.120× | 38.596 s | 1.024× | 5 tiles × 32 = 160 |
| Last 8 layers tiled | 8.639 s | 1.030× | 39.217 s | 1.008× | 5 tiles × 8 = 40 |

With 1 and 2 references, last-8 took 5.975 and 7.279 seconds vs 6.031 and
7.389 seconds decode-only: only ~0.9% and ~1.5% respectively. Three-reference
5-step last-8 was repeated in independent resident preparations with two
cached requests each: decode-only **8.909/8.892**, last-8 **8.637/8.653**
seconds, median ~1.030×. The input dump payloads matched, 40 added calls
per request, and both runs in each arm generated byte-identical PNGs to
their arm's earlier run. A separate 40-step last-8 repetition or broad
multi-seed quality qualification was **not** performed; its ~0.8% single-run
saving could be noise. A second seed-29 three-reference five-step pair took
**8.909 vs 8.664 s** (~1.028×), with identical input payloads and near
identical visible teapots and dragon (RGB correlation 0.9987); two seeds do
not qualify broad semantic fidelity. All tested Session probes passed cancellation, GPU route
switch and unload; `make test-qwen21` and `git diff --check` passed.

Visually, full-32 tiling **blurs/ghosts the dragon's eyes and sticker edge at
five steps** (RGB correlation to decode-only 0.973); despite a ~0.95-second
gain it is not appropriate for short-step editing. At 40 steps the sticker
recovers, but the blue pot shape differs and the benefit is only ~0.94 s.
Last-8 retains the dragon eyes, both teapots and the overall composition in
both inspected 5-/40-step images; it still changes sticker edge/teapot
details slightly (three-reference RGB correlations 0.9984/0.9983). This is
not a guarantee on other prompts, seeds or LoRA. Retain the opt-in for
further controlled experiments, but **keep decode-only as the conservative
supported quality tradeoff** until broader semantic checks justify promotion.

## 16-/24-layer sweep: same 1024-row graph, longer sequence

Two additional *opt-in, diagnostic-only* cutoffs were measured on the same
M4 Max. The first 16 or 8 first-step FFNs remain BF16 GPU; the final 16 or
24 use the 1024-row W8A8 Core ML graph once per sequence tile (3/4/5 tiles
for 1/2/3 resized-512 references). Four later steps retain the ordinary
32-layer hybrid FFN. The first step has 2091/3157/4226 actual text +
reference + target rows. Each arm was independently prepared, warmed and
then produced a 512² PNG with exactly equal text/noise/ordered-reference
latent dumps. Individual warm request walls include VAE, PNG and dumps.

| Inputs / steps | Decode-only W8A8 | Last 16 | Gain | Last 24 |
| --- | ---: | ---: | ---: | ---: |
| 1 reference, 5 steps | 6.031 s | 5.888 s | 1.024× | not run |
| 2 references, 5 steps | 7.389 s | 7.125 s | 1.037× | not run |
| 3 references, 5 steps, seed 17 | 8.898 s | 8.447 s | 1.053× | 8.228 s (1.081×) |
| 3 references, 5 steps, seed 29 | 8.909 s | 8.459 s | 1.053× | not run |
| 3 references, 40 steps | 39.535 s | 39.086 s | 1.011× | not run |

The three-reference five-step *same-input* BF16 GPU baseline was 10.114 s:
last-16 is about 1.197× faster, versus 1.137× for decode-only. This is not
a 1.3× short-step edit improvement. Last-16 added 80 Core ML predictions
in three-reference prefill; last-24 added 120; decode-only already made
128 calls over the remaining four steps. API calls do not prove physical
ANE residency.

Visual inspection: the single reference keeps the teapot shape but both
baseline and candidate miss the requested matte finish. Two-reference
output retains both teapots. Three-reference last-16 keeps both pots and
recognizable dragon eyes/outline for seeds 17 and 29, with small blue-pot
texture/sticker-edge differences. RGB correlations to decode-only are
0.9939 (seed 17), 0.9973 (seed 29) and 0.9930 (40 steps); these are **not**
semantic quality scores. Last-24 produces conspicuous double edges on the
blue pot handle at five steps (correlation 0.9878). Keep last-24 and all-32
diagnostic-only despite better single-run timings. Last-16 is an optional
short-step *research* tradeoff, not automatic CLI selection or a guarantee
for new prompts, references, LoRA, devices. The 1.1% 40-step gain needs
repetition before recommending it for long-step editing.

A separate candidate computed the BF16 GPU suffix over the entire sequence
once per layer while looping the same Core ML model over 1024-row tiles.
Three-reference last-16 five-step wall was **8.999 s**, slower than the
per-tile **8.447 s**. The candidate probe then failed its final GPU-switch
gate because its experimental flag remained set; the candidate and flag
were removed. Input materialization and shared-output copy barriers remain
possible limits, but this test alone cannot assign the 0.55 s regression.

## Explicit last-step hybrid FFN reuse: shorter 5-step editing

`TURBOCIDER_QWEN21_HYBRID_REUSE_FINAL_FFN_DIAGNOSTIC=1` is a separate
research switch for **five steps with last-16 first-step tiling**, 512² output,
1–3 resized-512 edit inputs,
checkpoint-matched W8A8, BF16 GPU complement and no LoRA. It is never
enabled automatically. On the penultimate step it captures an *independent*
copy of every hybrid FFN result **before the next Core ML prediction** can
overwrite its shared output; on the last step it reuses those FFN values
and runs attention and residual arithmetic normally. The first prefill step
and earlier decode steps retain their existing execution. This deliberately
changes denoising and requires `allow_approximation=true`. It can be combined
with `TURBOCIDER_QWEN21_TILED_PREFILL_W8A8_DIAGNOSTIC=16`; the former saves
32 Core ML predictions per five-step request, the latter adds 48/64/80
first-step predictions for 1/2/3 references respectively.

Single independent resident Sessions used five-step warmups for this new
route (compared with two-step warmups in the preceding table), then one
cached request including VAE, PNG and identical tensor dumps. These one-run
comparisons against earlier last-16/two-step-warmup controls are indicative,
**not strictly matched warmup**: 1-ref 5.888→5.558 s; 2-ref
7.125→6.791 s; 3-ref seed-29 8.459→8.071 s. Text/noise/reference-latent
payloads matched exactly, and verifier observed 32 fewer per-request
Core ML calls. Eye/outline, both teapots and the single red pot shape
remain visible; the one-reference matte instruction still fails in both
arms. RGB correlations against their last-16 controls were
0.99977/0.99972/0.99968; these do not establish general semantic fidelity.

The controlled seed-17 three-reference pair **did** use separate identical
five-step warmups and two cached requests per arm:

| Arm | Request 1 | Request 2 | Median |
| --- | ---: | ---: | ---: |
| Last-16 sequence tiles, no step reuse | 8.413 s | 8.402 s | 8.408 s |
| Last-16 + last-step hybrid FFN reuse | 8.091 s | 8.088 s | 8.090 s |

Both runs matched the actual input tensor payloads, and each reduced the
Core ML prediction count by 32. Their RGB correlation was 0.99967, RMSE
0.00844 (normalized RGB); both retain the ordered pots and sticker face
under visual inspection. This is about **1.04× faster than last-16 alone**
and about **1.25× faster than the earlier 10.114 s same-input plain GPU
control**, not the hoped-for general 1.3×. An earlier two-step-vs-five-step
warmup comparison gave the opposite 8.447→8.598 s direction, which is why
the matched warmups and repeats matter. The research switch does not qualify
a default, other prompts or long-step edits.

Combining existing `TURBOCIDER_QWEN21_METAL_QK_NORM_ROPE=1` with both
switches yielded 7.805 s in one seed-17 run (~1.30× vs old plain GPU),
but **visibly ghosts the blue teapot handle**; leave Q/K fusion off for this
quality-focused edit. Pure GPU and decode-only W8A8 paths remain unchanged:
after the new switch was disabled, the three-reference five-step decode-only
PNG was byte-identical to its pre-change baseline. The probe passed
cancellation, GPU switch and unload with the flags on.

Reproduce the better-checked short-step research candidate with an existing
request JSON that already opts into W8A8 and resized-512 references:

```sh
TURBOCIDER_QWEN21_TILED_PREFILL_W8A8_DIAGNOSTIC=16 \
TURBOCIDER_QWEN21_HYBRID_REUSE_FINAL_FFN_DIAGNOSTIC=1 \
build/native/turbocider generate models/Comfy-Org-Qwen-Image-2.1 EDIT_REQUEST.json
```

Individual PNGs and exact-dump comparisons are ignored under
`results/qwen21/session-ref512-edit*-w6144-*`; no model, image or Core ML
artifact is copied into the source tree by this diagnostic.

### Last-20 first-step tiles with final-step FFN reuse: screening only

The same fixed 1024-row W8A8 graph can be called 3/4/5 times per first-step
FFN for 1/2/3 resized-512 references. Increasing the tiled coverage from
the last 16 to the last 20 layers adds respectively 12/16/20 Core ML calls
per request; it does **not** change the attention sequence or avoid the
GPU/Core ML join at every tile. The following five-step comparisons also
enable the separate last-step hybrid FFN reuse in **both** arms. Input tensor
payloads matched exactly, and all sampled requests completed their resident
Session cancellation, GPU switch and unload checks.

| References / seed | Last-16 + step reuse | Last-20 + step reuse | Same-input speedup | RGB correlation |
| --- | ---: | ---: | ---: | ---: |
| 1 / 42 | 5.558 s | 5.525 s | 1.006× | 0.99993 |
| 2 / 17 | 6.791 s | 6.683 s | 1.016× | 0.99775 |
| 3 / 17, repeat 1 | 8.091 s | 7.964 s | 1.016× | 0.99591 |
| 3 / 17, repeat 2 | 8.088 s | 7.982 s | 1.013× | 0.99591 |
| 3 / 29 | 8.071 s | 8.004 s | 1.008× | 0.99722 |

The three-reference seed-17 pair used identical five-step warmups and two
cached requests in each arm. The other rows are single independent resident
preparations, also with five-step warmups. These are **not** thermal/device
population confidence intervals. In the PNGs, one reference preserves the
pot shape, two preserve both pots, and three preserve both pots and the
sticker's face, but the last-20 output makes the blue handle double edge
more apparent for seed 17; seed 29 has handle/teapot-detail differences too.
The red pot still fails the matte-finish instruction in both arms. The
last-20 combination saves at most ~0.13 s in these requests, so keep it
historical screening evidence, not a quality-qualified faster preset. The
plan gate no longer allows **last-20 plus final-step reuse**; stand-alone
last-20 remains a diagnostic, and last-16 + step reuse remains the
better-checked short-step tradeoff.

For the last-16 + step-reuse path, materializing the GPU/Core ML merged tile
result directly (instead of copying that newly allocated result once more)
produced byte-identical PNGs in two three-reference seed-17 requests.
After the final rebuild, single- and two-reference five-step requests also
matched their pre-change last-16 + step-reuse PNGs byte-for-byte (5.551 s
and 6.774 s respectively, one warm request each).
The original 8.091/8.088 s became 8.078/8.075 s with the extra copy removed;
this ~0.013 s difference is too small to establish a repeatable speedup.
The result must still be evaluated **before** the next Core ML call reuses
its output backing. The conservative materialization barrier stays.
Against a separately prepared **plain BF16 GPU** Session with identical
five-step warmup, seed-17 three-reference requests took 10.116/10.149 s
GPU versus 8.078/8.075 s last-16 + reuse: median **1.255×** end-to-end.
Actual dumped text/noise/ordered reference latents matched, and the visual
inspection found both teapots and dragon face in both outputs (RGB
correlation 0.99246 is not a semantic score). This comparison isolates the
same-input acceleration from reference downscaling: both arms resize each
reference to 512px. It does **not** establish a 1.3× gain, native ANE
residency, or general editing quality across diverse inputs.
An attempt to compute the GPU suffix on only the valid rows of the final
partial tile was **reverted**: three-reference PNGs happened to match, but
the one-reference image no longer matched byte-for-byte (RGB RMSE 0.00281)
and its wall worsened 5.558→5.621 s with equal input dumps. There is no
qualified short-tail optimization in the final path.

An independent `qwen21-qkv-probe` also screened a fused Metal Q/K/V projection
for 1024/3157/4226 rows. Concatenating the three GEMMs alone measured about
7.09→7.14, 29.09→29.13, 91.21→90.62 ms; a fused Q/K norm-RoPE variant
at BM32 measured 7.17→7.02, 22.01→21.42, 29.57→28.69 ms at
1024/3157/4226 rows, with projection-output relative L2 about 1e-5.
This is a small **isolated projection** saving, not end-to-end speedup or
quality approval; `native/models/qwen21/metal/qkv_projection.hpp` has not
been wired into production. A previous fused Q/K edit screen visibly
ghosted the handle, so it cannot be assumed safe from projection error alone.

The reference-shrink speedup (older three 1024px references: 25.107 s at
five steps, 82.303 s at forty; same three *resized*-512 references: 10.114 s,
52.327 s on GPU) is an input-fidelity/sequence-length tradeoff, **not a
GPU kernel or ANE speedup**. Compared with `../splash`, which packs fixed
2048-row shared Metal buffers and schedules GPU FFN complement concurrently
with Core ML before the join, this Qwen21 diagnostic uses MLX materialization
at each tile/block boundary. Each first-step block still runs its attention
and sequential tile predictions; the 512px 1-/2-/3-reference first step has
3/4/5 tiles. Smaller sequences cut the number of calls and copied FFN
results, but full-prefix quantization changes the conditioning and little
of the total 40-step wall is saved by first-step-only offload. A future
candidate needs either a better first-step exact GPU kernel/attention path
or less synchronization and materialization across GPU/ANE, with end-to-end
same-input/semantic validation.

## W8A16 GPU complement versus BF16 GPU complement

For the same three resized-512 references and the **same 6144-channel W8A8
Core ML graph**, the existing optional `qwen21_gpu_w8a16=true` quantizes
the complementary GPU FFN projection weights to W8A16. The separate
resident Sessions each performed the same prepare/two-step warmup, cached
request and equal input dumps. The verifier matched text, initial noise,
all three reference latents, checkpoint/manifest geometry and 32-layer Core
ML call counts. One run per arm; timings include VAE/PNG/dumps:

| Steps | W8A8 Core ML + BF16 GPU | W8A8 Core ML + W8A16 GPU | Verdict |
| ---: | ---: | ---: | --- |
| 5 | 8.898 s | 9.209 s | W8A16 ~3.5% slower |
| 40 | 39.535 s | 42.793 s | W8A16 ~8.2% slower |

At five steps, the two teapots and central sticker remain recognizable;
40-step W8A16 also retains them, with small teapot/sticker differences.
The five-/40-step BF16-to-W8A16 RGB correlations are 0.9995/0.9897.
Quality alone cannot rescue a **slower** FFN complement. This is an actual
end-to-end check consistent with the earlier isolated GEMM screen; keep the
BF16 GPU suffix as the faster route on this checkpoint/device. The outputs
and verified comparisons are in ignored `results/qwen21/session-ref512-edit3-w6144-w8a16-*`.

Raw receipts/PNG/verified comparison JSON under the ignored
`results/qwen21/session-ref512-edit*-{gpu,w6144}*` directories are local
evidence. The diagnostic flag and model path are deliberately absent from
normal CLI defaults; use an explicit manifest and request only for research.
