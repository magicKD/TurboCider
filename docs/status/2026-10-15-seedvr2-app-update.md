# 本机 App 更新与 SeedVR2 超分入口

2026-10-15，Apple M4 Max / 64 GiB，macOS 26.6.2。功能提交 `f5dcaf5`。

已将原来运行的 `dist/TurboCider.app` 更新为合并后的完整 App，并在正常退出旧进程后从同一路径重新打开。新 App 有可见主窗口；原有 6 条历史、4 个模型路径、当前 Z-Image 创作模式均保持不变。没有下载模型或删除源媒体。

## 直接测试

1. 左侧点击 **SeedVR2 超分**，在 **图片 / 视频** 间切换。
2. 添加源媒体。本机已有完整 SeedVR2 DiT/VAE 登记，可直接使用；模型中心的 **超分** 和 **视频** 分类也能找到 SeedVR2。
3. 选择 **2× / 4× / 长边 512 / 长边 1024**，再点 **开始图像超分 / 开始视频超分**。建议先用 512/1024。
4. 图片保存为 PNG；视频保存为无音轨 MP4，结果进入现有历史。原媒体保留，任务可取消。

尺寸预设按源尺寸计算并对齐 16 像素；超出当前 2048 单边或短边不足 64 时明确报错，不静默裁剪。采样固定 1 步，不使用提示词。视频的完整帧数/FPS从源文件读取并锁定，当前仅支持 2–121 帧、整数恒定源 FPS，不自动截帧/补帧。

**省内存建议** 是显式按钮，复用既有 staged/VAE 建议，不构成硬内存保证。右侧高级设置可调驻留；详细 VAE 选项仍在模型中心的 **加速与编译缓存** 中。Real-ESRGAN 的辅助 x2/x4 工作区、普通创作与 Playground 保持独立可用。

## 构建、发布与验证

- 最终构建：`build/seedvr2-app-public-20261015/`，公有 API、Private ANE 关闭，test hooks/audit/未验收 VAE 实验关闭。
- Native identity：`tc-runtime-build-v1-4e8be37be47f87c3918fe9afec1df909ecb5aeb7c71bc74f624b3b1a310531fd`；648 份 native 源摘要与当前树一致。
- 稳定发布门禁同时检查 flags、实际类名/符号/链接，随后本地 ad-hoc 签名；最终包通过 `codesign --verify --deep --strict`。不是公证发行签名。
- App、原生库、CLI、模型库助手、H3 缓存助手的全部 `__TEXT` section 与已测公有构建逐项一致；打包仅作路径调整/签名。MLX Steel/vpipe 归属和许可也补入 App/CLI 资源。
- 仓库检查 17 项、发布门禁 10 项通过；最终公有库公共请求合同 129 项（1 条条件跳过）通过。
- SeedVR2 新入口/图片视频模式、输出预设、越界不修改草稿、异常源尺寸、导入中禁止切换、完整帧数/FPS，以及模型中心混合输出分类回归通过。

同一 Swift `StudioState` / `NativeJobStore` / C ABI 工作流对最终公有库完成 7 个真实任务：

| 任务 | 输出验证 |
| --- | --- |
| 图像 512×512 | PNG 解码、尺寸、单步、原始稳定 FP16/FP32 配方、历史通过 |
| 图像 1024×1024 | 同上，RGBA 与先前测试构建逐字节一致 |
| 视频 512×512，25帧/24FPS | H.264 MP4，无音轨，完整25帧；每帧解码像素与先前构建一致 |
| 视频 1024×1024，25帧/24FPS | 同上，完整25帧，无隐式截帧/改帧率 |
| resident → component_staged → resident | 额外3个真实图像任务；驻留执行/释放回执正确，PNG完全一致 |

两张 PNG 均与先前测试构建文件逐字节一致；视频容器文件字节不同，但全部解码帧像素相同。此处是更新功能/回归验证，不是新配对性能或广泛画质认证。

首轮尝试沿用 benchmark 的 Private ANE 库时，打包门禁在替换任何 App 前正确拒绝；随后按标准公有模式重新构建，没有放宽门禁。发布测试中原有 targeted-build 文本断言同步适配了已合并的 `APP_TARGETS` 变量，并增加完整 App/助手/测试顺序检查。一次公共合同测试与真实推理并发得到 GPU busy；真实推理退出后串行重跑通过，失败日志保留。

系统未授予辅助访问与屏幕录制权限，因此没有执行自动点击或截图验收；已确认最终进程从规范包路径运行且主窗口在屏幕上。没有绕过系统授权。
