# Qwen Image 2.1：512² 纯 GPU Q/K norm＋RoPE 融合消融

Apple M4 Max、BF16 Comfy checkpoint。新增显式实验开关
`TURBOCIDER_QWEN21_METAL_QK_NORM_ROPE=1`，把每层 Q/K 投影之后的
128 维 RMSNorm、RoPE、token-major→head-major 输出布局合在一个
Metal kernel；替代原有成对 RoPE，不得同时启用两个开关。
只接受 `execution=gpu`、512×512、`allow_approximation=true`；默认
GPU 和既有 W8A8 GPU/ANE 均未改变。kernel 输入仍为 BF16 投影，旋转
表为 FP32；它省掉中间 materialization，但因为规约和 BF16 舍入顺序
不同，**不宣称逐位等价**。单层随机 BF16 单测覆盖 17/1024/1048
tokens，Q 相对旧成对 RoPE 的 relL2 为 0，K 约 0.00325。

每路线独立进程，先 prepare、2 步 warmup，再两次同输入、条件缓存
命中的请求；每轮墙钟包括 VAE、PNG 和两路线同样的输入张量转储，
不包括准备／首次加载。对照和候选的文本、初始噪声与每张编辑参考
张量逐项相同。均只是一组 prompt/seed，非普适画质验收。

40 步双参考两只茶壶的构图、左右顺序和壶嘴／把手目视接近；
5 步三参考里茶壶和中央贴纸可辨，轮廓有细微差异；单参考
要求哑光红壶，但基线和候选都偏亮。文生图 5 步狐狸仍偏软。
这些检查只针对上述图像，尤其不能以相关性数字代替参考忠实度。

将新融合与**末步 FFN 复用**叠加，并和旧“成对 RoPE＋末步 FFN
复用”在相同条件比较：文生图另一个 5 步狐狸输入的旧／新分别
是 5.229/5.203 s 和 5.215/5.181 s（约 1.003×）；双参考
5 步是 5.891/5.905 s 和 5.859/5.888 s（约 1.004×）；
双参考 40 步是 43.310/43.311 s 和 43.176/43.202 s
（约 1.003×）。三组输入均逐项核对，图片相关性分别约
0.99926、0.99886、0.99944。约 0.3–0.4% 的组合增量接近
两轮测量波动，不把它称为稳定的新最快生产方案。上述组合文生图
使用另一条 31-token 提示词，不能与表中 24-token 对照混算。

瓶颈仍主要是 FFN 大矩阵乘，单层插桩记录的 gate/up＋down 约
22.6 ms／层，而 Q/K norm＋RoPE 约 3.5 ms／层；插桩会改变调度，
不能将比例直接作为未插桩占比。融合只影响 Q/K 小段，不会改变
GPU/ANE FFN 的划分。原有 6144-channel 32/32 W8A8 混合方案在
匹配的双参考缓存请求约 5.459/5.414 s（5 步）和
31.962/31.985 s（40 步）；分别比本次最快融合＋末步复用
约快 1.080×、1.351×，但双参考 40 步的混合出图相对基线
RGB correlation 约 0.944、参考形状有所偏移，且 Core ML 的
`CPU_AND_NE` 不证明物理 ANE 驻留。不能仅靠速度替换默认 GPU。
现有并行按 FFN hidden channel 切分 6144／6144；改成 token
sequence 切分需重新 export／编译 Core ML 输入 rows、处理动态
参考／文本 token 和跨设备同步，此轮没有实测，不能声称更快。

此候选目前只通过真实模型的 5 步文生图、1–3 参考编辑和双参考
40 步。运行 `build/native/turbocider plan request.json` 可检查显式
门禁和近似标记，再用同一环境变量运行 `generate`；未验证更广泛的
提示词、硬件、冷启动和全部 40 步编辑类型。正式 CLI 默认维持
此前测试过的显式成对 RoPE＋末步 FFN 复用，GPU/ANE 保留已有的
W8A8 选择，不自动启用新 kernel。原始每轮 PNG/JSON 与输入转储
在被 Git 忽略的 `results/qwen21/session-gpu-qknorm-*`，配对报告
为同前缀的 `*-comparison.json`。

`qwen21_metal_qk_norm_rope`；这次冷进程功能冒烟不参与上表
