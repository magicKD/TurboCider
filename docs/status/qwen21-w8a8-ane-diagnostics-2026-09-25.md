# Qwen-Image-2.1 512² W8A8/ANE 诊断

日期：2026-09-25。本文先记录基于实际 512² 生图第二步、缓存 prefix KV 的
block 0 FFN 输入 `[1024,4096]` 所做的离线实验；后文另列 32 层离线
检查及 512² 生图诊断。**这些结果均不是生产 Session 的 W8A8 验收**。
32 层校准输入位于忽略的 `results/qwen21/qwen21-w8a8-calibration-512-teapot/`；
文档中的本机模型产物、报告也不进入 Git。可用
`tools/native/qwen21_transformer_probe.cpp` 提取 FFN 输入，以
`tools/coreml/export_qwen3.py` 导出单层隔离模型，并用
`tools/validation/qwen21_a8_boundary_compare.py` 对同一输入比较
Core ML `CPU_ONLY` 和 `CPU_AND_NE`。计算设备策略不是物理 ANE 驻留证明。

## 已测结果

同层 W8A16（仅权重量化）相对 BF16 分支的 RMSE 为 `0.02064`，
Core ML prediction 中位数 `9.26 ms`。原 W8A8 的相对 BF16 RMSE 为
`0.91408`，prediction 中位数约 `8.34 ms`：单层调用略快，**输出不合格**。
即使 CPU_ONLY 相对 BF16 只有约 `0.09255` 的 RMSE，CPU_AND_NE 对
CPU_ONLY 的 RMSE 仍约 `0.91270`。该速度差不能外推到 GPU+ANE 的
32 层/5 步或 1024² 加速比。

进一步隔离同一实测输入（下表均为 `CPU_AND_NE` 相对 `CPU_ONLY` 的
relative RMSE；数值来自忽略目录下的对应 compare JSON）：

| 上投影 / hidden / down | 对比结果 |
| --- | ---: |
| W8，仅 input A8；无 hidden A8，完整分支 | 0.02165 |
| W8，hidden A8，W8 down，完整分支 | 0.91270 |
| W8，hidden A8，FP16 down，完整分支 | 0.91266 |
| FP16 上投影，hidden A8，W8 down，完整分支 | 0.04170 |
| W8，仅 input A8，在 down 前输出 SwiGLU | 0.06130 |
| W8，input/hidden A8，在 down 前输出 hidden | 0.90285 |
| FP16 上投影，input/hidden A8，在 down 前输出 hidden | 0.13686 |

后两组 hidden tap 不含 down，不能替代完整分支画质测试；但它们把当前
`CPU_AND_NE` 失真定位在 **W8 上投影与 hidden A8 的图组合中、进入 down
之前**。把 hidden A8 改成 uint8、把 down 切成两段、把上投影后 SwiGLU
暂转 FP32 均未改善：各自的单层对比结果约为 `0.91267`、`0.91267`、
`0.91270`；将 fused gate/up W8 卷积拆成两个独立 W8 卷积，结果也仍为
`0.91270`。把 hidden `dequantize` 换成显式 INT8 `cast × scale` 后仍为
`0.91271`。简单统一输出增益也不是修复：拟合增益约 `7.14×` 后仍剩
`0.599` relative RMSE。相应离线 JSON 为
`qwen21-a8-amplitude-compare-512.json`、
`qwen21-hidden-input-vs-both-tap-512.json`、
`qwen21-a8-projected-down-isolation-512.json` 等。

这些现象提示 Core ML 对该图的 ANE 路径与 CPU 路径不等价，尚不能在
没有内部中间值/设备轨迹的情况下断言具体是哪一个 ANE kernel 或编译 pass。
后续应先找到数值正确且能证明 ANE 驻留的**双 W8 + 双 A8**单层图；
再测未用于校准的提示词/编辑输入、至少 29/32 层覆盖率、512² 文生图和
1–3 张参考图编辑的实际视觉效果、GPU/ANE 同条件端到端性能；后续
诊断实验的进展与未通过项见下文。

## 修正权重量化粒度后的后续证据

上面严重的 CPU/ANE 差异并非所有 W8A8 图的必然结果。改变 **gate/up W8**
的压缩粒度，保留双 A8 和 W8 down、相同校准输入与 SmoothQuant：

| gate/up W8 布局 | 茶壶 block 0 CPU/ANE rRMSE | 狐狸 block 0 对 BF16 rRMSE | 真实 C ABI 单层调用中位数 |
| --- | ---: | ---: | ---: |
| per-channel（旧失败图） | 0.91270 | 未重新测试 | 8.34 ms（旧图） |
| per-block / 32 | 0.00979 | 0.07948 | 14.30 ms（茶壶） |
| per-tensor | 0.04204 | 0.08614 | 6.79 ms（茶壶），7.07 ms（狐狸） |

per-tensor 模型在校准茶壶的 hybrid FFN 输出相对 BF16 为 `0.03543`，
独立狐狸输入为 `0.03129`。狐狸输入来自另一真实 512²/40 步 GPU
生图的文本和初始噪声；通过原生探针复用 prefix KV，在第二步提取全部
32 层 FFN 输入，未加入茶壶校准目录。用茶壶尺度导出、编译全部
**32/32 层**，在狐狸输入上逐层检查，相对 BF16 ANE 分支 rRMSE
约 `0.067–0.296`；其中 block 3–7 明显较高。Core ML 源 `.mlpackage`
逐层进程中的约 12 ms 调用与 C ABI 已编译模型约 7 ms **不是同一
benchmark 边界**，不能以逐层源包测量否定或替代已编译速度。

独立诊断生成器在同一狐狸提示词、seed 42、512²/40 步下完成 GPU 与
GPU+ANE 两次请求：文本、初始噪声和 sigmas 逐项一致；后者执行
`39 × 32 = 1248` 次 Core ML FFN，记录 output copy `0`。GPU 去噪
逐步之和 `42.503 s`，混合 `34.838 s`，比例 `1.220×`；不同进程的
完整首次请求分别 `45.262 s` 和 `44.577 s`，混合还需模型加载，
**这不是重复 warm Session 提速证明**。两张 40 步狐狸输出均是清晰的
狐狸与雪景，目视姿态、主体与构图接近，毛发局部存在差异；RGB
correlation `0.98737`、RMSE `16.57/255`，latent rRMSE `0.08405`。
5 步输出也接近，但两张都明显模糊，不作为最终画质门槛。

实测文件保留在被忽略的 `results/qwen21/` 下：
`qwen21-w8a8-projected-tensor-heldout-fox-all32-report.json`、
`qwen21-w8a8-heldout-fox-layer0-compare.json`、
`w8a8-b0-projected-tensor-heldout-fox-report.json`、
`qwen21-w8a8-fox-{gpu,hybrid}-512-{5,40}.png`。但仅有一组未校准
提示词、一个 seed、单机和独立诊断调用，仍须测试重复 warm Session、
多 prompt/seed、生产级 1–3 张参考图编辑与实际设备驻留/重叠。GPU 后缀
已增加显式 W8A16 研究选项，但下面的对照尚不支持替换更快的 BF16
后缀；默认策略不得据此自动改成 W8A8。

## GPU 后缀 W8A16 与 BF16 同条件对照

诊断生成器显式 `--experimental-w8a8 --experimental-gpu-w8a16` 可把全部
32 层 GPU FFN 后缀的 gate/up 和 down 权重在加载时打包为 MLX affine
W8（64 通道组）；运行时两次 GPU 矩阵乘的激活保持 BF16，ANE 前缀
仍是 per-tensor gate/up W8、双 A8 的完整 32 层图。后缀输出显式转
回 BF16，避免量化矩阵乘返回不同 dtype 破坏下一步的 text/latent
精度约束。该开关只在独立诊断生成器可用，不进入生产 Session。

用同一未校准的狐狸提示词、seed 42、512²/40 步，与前文 BF16 后缀
W8A8 及纯 GPU 的保存张量逐项匹配（文本、初始噪声、sigmas 均一致）：

| 方案 | 去噪逐步时间之和 | 后续步中位数 | 相对纯 GPU 去噪 |
| --- | ---: | ---: | ---: |
| 纯 BF16 GPU | 42.503 s | 1.060 s | 1.000× |
| BF16 GPU 后缀 + W8A8 Core ML | 34.838 s | 0.844 s | 1.220× |
| **W8A16 GPU 后缀 + W8A8 Core ML** | 38.935 s | 0.956 s | **1.092×** |

W8A16 图对 BF16 后缀混合图的 RGB correlation 为 `0.99949`，
RMSE `0.00674`（`[0,1]`），latent rRMSE `0.01395`；对纯 GPU
correlation 为 `0.98903`。W8A16 图片仍为清晰的雪地狐狸，姿态和
主体接近；该样本的精度并非瓶颈，但 **W8A16 比 BF16 后缀慢约
11.8%（去噪耗时）**，因此保留 BF16 为目前最快的实验路线。首次完整
W8A16 请求为 `47.767 s`，包括加载与当次量化，不能当作 warm
Session 提速。后一方案执行了 `1248` 次 Core ML 预测、output copy
记录为 `0`；未证明物理 ANE 驻留。报告和图片位于忽略目录下的
`qwen21-w8a8-fox-w8a16-vs-{bf16,gpu}-512-40.json` 及
`qwen21-w8a8-fox-w8a16-512-40.png`。5 步配对也已运行，但两张
5 步图本身模糊，只作为输入一致/类型与时序 smoke，不作画质验收。

## 参考图编辑：质量与加速并非随参考图数量单调改善

用同一张茶壶、蓝色茶壶和橙色龙贴纸作最多三张参考图，对独立诊断
生成器进行了 512²/40 步、seed 42 的匹配 GPU 与 W8A8 混合请求。
CPU 比较器逐项核对文本 embedding、初始噪声、sigmas、图像槽位以及
每张参考图的 VAE latent；补充了缺失或不同参考张量必报错的测试。
三参考图还用**与生产编辑相同的 1024 像素参考缩放**重新跑了一组，
此前 1–3 图的历史组则直接使用原始 512/1024 参考尺寸，两种输入不可
相互充当同条件性能对照。

| 请求及参考尺寸 | GPU 后续步中位数 | 混合后续步中位数 | 去噪总加速比 | RGB correlation | 目视检查 |
| --- | ---: | ---: | ---: | ---: | --- |
| 1 图，原尺寸 | 1.106 s | 0.890 s | 1.213× | 0.99833 | 两图茶壶接近 |
| 2 图，原尺寸 | 1.290 s | 1.145 s | 1.112× | 0.99809 | 两图均只呈现第一把茶壶 |
| 3 图，原尺寸 | 1.350 s | 1.455 s | 0.944× | 0.99755 | 两图均只呈现第一把茶壶 |
| 3 图，生产同款缩放 | 1.626 s | 1.774 s | **0.936×** | 0.99708 | 两图均只呈现第一把茶壶 |

最后一组完整首次请求为 GPU `90.701 s`、混合 `103.468 s`；后者有
`1248` 次 Core ML FFN 调用、`14.825 s` 累计预测时间、`6.849 s`
加载时间，记录 output copy 为 `0`。匹配输入的 latent rRMSE 为
`0.08858`，RGB RMSE `0.02423`（以 `[0,1]` 为单位）。三图缩放对照
去噪和整次请求均比纯 GPU 慢，不能用单参考图的加速比代表多参考性能。
两条路径都漏掉了蓝茶壶和龙，**本例不能作为三主体编辑质量通过的

请求实现和输入不同，也不能替代本例验收。

配对报告在忽略目录 `results/qwen21/qwen21-w8a8-edit{1,2,3}-512-40-comparison.json`
及 `qwen21-w8a8-edit3-resized-512-40-comparison.json`；PNG 与相邻
`.safetensors` 供目视和输入复核。更长参考 prefix KV 与统一内存竞争
可能限制 FFN 并行收益，但当前计时不含足够的算子级轨迹，**不能据此
确认瓶颈**。诊断生成器现已对齐生产参考缩放；尚需重复 warm Session、
生产编辑质量门禁和其它 seed/prompt，并研究不增加质量损失的多参考
加速策略。

### 生产路径一致性与逐步耗时定位

用正式 `turbocider generate` 以同一 prompt、seed、三张参考图、512²、
40 步、纯 GPU 生成，和对齐生产参考缩放后的诊断 GPU PNG **逐像素
完全一致**（RGBA max absolute difference `0`）。正式请求的
`reference_tokens=12288`、去噪 `81.504 s`；两者都只出现第一张参考图
的茶壶。这次缺少蓝茶壶和龙并非 W8A8 的量化误差，也不是诊断生成器
参考预处理与正式 CLI 的偏差；但只核对一个 prompt/seed，不能断言
所有 512² 多参考图都不可能正确生成。

诊断生成器现在把每个去噪步的 Core ML **prediction API 墙钟耗时**
及 FFN 调用次数保存到 `.safetensors`，比较器检查第一步为 0 次、
后续每步 32 次，拒绝不合理/缺失计时。相同 512² 输出行数、同一
32 层 W8A8 manifest、BF16 GPU 后缀和 40 步条件下：

| 工作负载 | 后续步 Core ML API 中位数 | 平均到单次 FFN 的中位估算 | 混合后续整步中位数 |
| --- | ---: | ---: | ---: |
| 狐狸文生图 | 0.214 s | 6.68 ms | 0.845 s |
| 三张 1024² 参考图编辑 | 0.333 s | 10.42 ms | 1.787 s |

三参考下 Core ML API 耗时约为文生图的 `1.56×`，即使 FFN 输入形状
和图相同。三参考的配对 GPU 后续步中位数仍为 `1.626 s`；本次混合
去噪总加速比为 `0.944×`，方向与上表先前 `0.936×` 的配对一致。
Core ML API 时间含框架调度且和 GPU 分支重叠，**不能从整步时间
直接扣除**；逐步计时证明 API 调用变慢，但无法单独确认芯片驻留、
内存带宽或调度何者为根因。数据文件为忽略目录的
`qwen21-w8a8-{fox,edit3-resized}-profile-512-40.png.safetensors`
与相邻的 `-comparison.json`。在完成多机器/多 seed 的质量与速度
门禁之前，不把三参考图请求自动切换到 W8A8 混合路径。

### 缩小参考前缀及少量 FFN 层回退：512² 三参考候选

为区分输出尺寸与参考前缀长度的影响，独立生成器现在支持显式
`--reference-size=256|512|1024`；正式 CLI 默认仍使用原有的
1024 像素参考缩放，256 缩放须显式请求，**这是不同的任务输入，不与
默认图作像素一致性的质量声明**。另有显式 `--experimental-gpu-ffn-blocks=3,5,7`：
这些层的完整 BF16 FFN 走 GPU，其余 `29/32=90.625%` 解码 FFN
保持 W8A8 Core ML 前缀与 BF16 GPU 后缀并行。代码拒绝超过三层
GPU 完整回退、重复/非法层号；逐步计数及比较器共同核查覆盖率。
选择层号参考前文狐狸独立输入的逐层误差排序（block 5、7、3 居前），
不是利用本组三参考输出拟合新的权重或量化尺度。

相同三参考图提示词、512²/40 步、两个 seed 的诊断结果：

| seed / 参考缩放 / FFN 路线 | 三个主体目视可辨 | 后续步中位数 | 相对匹配纯 GPU 去噪 | RGB correlation（匹配输入） |
| --- | --- | ---: | ---: | ---: |
| 42 / 1024 / GPU | 否，仅米色茶壶 | 1.626 s | 基线 | — |
| 42 / 256 / GPU | 是，蓝茶壶与龙较小 | 1.099 s | 基线 | — |
| 42 / 256 / 32/32 W8A8 | 否，蓝茶壶丢失 | 0.883 s | 1.206× | 0.94392 |
| **42 / 256 / 29/32 W8A8** | **是** | **0.903 s** | **1.186×** | **0.99716** |
| 17 / 1024 / GPU | 是 | 1.62 s 左右 | 基线 | — |
| 17 / 256 / GPU | 是 | 1.099 s | 基线 | — |
| 17 / 256 / 32/32 W8A8 | 是 | 0.883 s | 1.212× | 0.99504 |
| **17 / 256 / 29/32 W8A8** | **是** | **0.903 s** | **1.186×** | **0.99155** |

29 层候选每个解码步实测 29 次 Core ML 调用，即 40 步合计
`39×29=1131` 次，Core ML output copy 为 `0`；每步预测 API
中位约 `0.194–0.195 s`。seed 42 完整首次请求为 `47.882 s`，
纯 GPU 256 参考组为 `48.650 s`：本组的主要好处是热去噪阶段，
不能把单次冷请求报告为 `1.186×`。seed 17 的两次首次请求分别
约 `47.867 s`、`47.744 s`。缓存/模型加载和短步请求仍需要
独立暖 Session 复测。

这证明“缩小参考图 + 有限 GPU 层回退”在**同提示词两个 seed**上
能兼顾三主体可见、至少 90% W8A8 FFN 覆盖和接近 1.19× 的
去噪提速，不证明其它题材/参考图、文生图 5 步、生产 CLI 质量
或硬件 ANE 驻留。缩小参考图会损失细节、改变构图，seed 42 的
蓝茶壶尤其偏小；seed 17 的默认 1024 参考图本来就能呈现三主体，
因此不能声称大参考图普遍错误。报告与 PNG 位于忽略的
`results/qwen21/qwen21-edit3-ref256-*-512-40*`，配对结果文件包含
输入逐张相等检查、latent/RGB 误差与 29/32 覆盖核查。

正式 Session 目前允许显式选择已校验的 32 层 FP16 文生图 manifest，
或显式选择 per-tensor W8A8、256 参考缩放、3/5/7 层 GPU 回退的
512² 1–3 参考图编辑 manifest；默认 GPU 路线不改变。Session 核验
checkpoint SHA、图身份、输入行数、实际 FFN 调用次数；这不等于
W8A8 质量验收或物理 ANE 驻留证明。1024² 的配对诊断结果见
`qwen21-w8a8-ane-1024-diagnostics.md`，但正式混合请求仍限制 512²。
512² 的 1024 行模型/速度不能外推到 1024² 的 4096 行 FFN；
Z-Image 的历史 1024² 速度也不属于本模型。

### 相同双参考图的 resident 编辑条件复用

正式 Qwen Session 新增一条内存中的编辑条件缓存：相同提示词、参考缩放、
**有序参考文件内容 SHA-256** 才复用文本/视觉条件和参考 VAE latent；
编码完成前再次核对文件内容，覆盖同名参考文件会失效并重新编码。
去噪 prefix KV 仍每次请求建立；检查文件 SHA-256 的时间包含在墙钟中。
探针覆盖引用自身输出目录中的参考图副本，不修改原参考文件，验证
cache miss 后再次请求会命中。生产默认路径及输出质量验收结论未改变。

匹配的 512²、40 步、seed 17、两张参考图缩至 256、相同输入的
resident Session：每路线先准备及预热，接着连续两次 cache hit。纯 GPU
请求墙钟 `44.733/44.777 s`、去噪 `44.152/44.191 s`；29/32 层 W8A8
Core ML 前缀加 BF16 GPU 后缀墙钟 `37.159/37.176 s`、去噪
`36.548/36.555 s`。两轮均值分别约 **1.204× 端到端**和
**1.208× 去噪**。同条件 5 步两轮为 GPU `6.688/6.727 s`、混合
`6.012/5.999 s`，墙钟约 **1.117×**。旧版每次重编条件的 5 步
`0.835×` 和 40 步 `1.130×` 不可当作新缓存命中的测试结果。
各路线的连续两轮 PNG 分别逐字节相同；每轮混合 40 步新增 1131 次
Core ML 解码 FFN 调用，5 步新增 116 次，output copy 为 0。
报告位于忽略目录
`results/qwen21/session-{gpu,hybrid}-edit-cache-v2-512-40/` 和对应
5 步缓存探针目录。这是**相同编辑输入的暖请求**，未覆盖新参考/提示词、

### Resident Session 双参考热请求

扩展 `qwen21-session-probe` 接受正式 CLI 请求文件（保持相同 prompt、
参考文件、seed、256 参考缩放和 40 步），在每条路线各自的常驻 Session
完成 prepare、2 步 warmup 后连续生成两轮；GPU 与 W8A8 混合的
请求顺序运行，不并发争用 GPU。每轮编辑仍重新编码参考图和文本；
这里的 warm 只指模型 Session 已加载，并不意味着整条请求输入被缓存。
结果保存在忽略目录 `results/qwen21/session-{gpu,w8a8}-edit2-ref256-512-40/`。

| 路线 | 第 1 轮请求墙钟 / 去噪 | 第 2 轮请求墙钟 / 去噪 |
| --- | ---: | ---: |
| BF16 GPU | 45.787 / 44.169 s | 45.766 / 44.170 s |
| W8A8 + BF16 GPU | 40.353 / 36.880 s | 40.661 / 36.915 s |

两轮合并墙钟比例 `1.130×`、去噪比例 `1.197×`。同一路线两轮 PNG
逐像素相等；GPU 对混合 RGB correlation `0.995856`、RMSE
`0.027053`（`[0,1]`）。混合 runtime calls 从 warmup 后的 `29`
分别增至 `1160`、`2291`，即每轮新增 `39×29=1131`；Core ML
load_seconds 保持 `13.495 s`，output copy 为 `0`。探针还通过了取消后
切回 GPU 的生命周期断言。这是**单机、一个 prompt/seed、两轮热
Session**的有效端到端证据，不覆盖其它参考图、5 步场景或物理 ANE
驻留，也不改变默认 GPU 策略。

用同一双参考请求改为 **5 步**，仍在各自常驻 Session 内 prepare、
2 步 warmup 后跑两轮：纯 GPU 墙钟 `7.880/7.688 s`、去噪
`6.124/6.086 s`；混合墙钟 `9.033/9.620 s`、去噪
`5.846/5.733 s`。合并两轮得到去噪 `1.054×`，但请求墙钟仅
`0.835×`（混合更慢）。每轮仅 `4×29=116` 次 W8A8 runtime
FFN 调用；参考图和文本每次重编码，混合文本耗时
`2.42/3.15 s` 对比 GPU `1.02/0.86 s`，是这次短请求整体
落后的主要观测项，不能仅据此断言具体设备竞争原因。
检查这批保存的 `run-*.json` 后确认两条路线的
`prompt_cache_hit` 均为 `false`；不能把此 `0.835×` 写成**条件缓存命中**
时的结论。
5 步 GPU/混合 RGB correlation `0.999068`，但两图都偏软，
不用于最终画质验收。报告位于
`results/qwen21/session-{gpu,w8a8}-edit2-ref256-512-5/`；
短步编辑继续默认选 GPU，W8A8 只供明确 opt-in 实验。

### 显式 6144-channel W8A8 分区复测

从相同真实 512² 茶壶 FFN 校准输入导出 1024 行、32 层、`[0,6144)`
per-tensor gate/up W8＋双 A8 的 Core ML 模型；GPU 后缀为 BF16，
层 3/5/7 完整回退 GPU。生产 Session 只接受完整 32 层、同 checkpoint、
正确 row/shape 的显式 manifest；FP16 分区仍限 `[0,4096)`，
默认 `gpu` 保持不变。单层完整 FFN 的茶壶/独立狐狸 rRMSE
`0.0379/0.0339`，高于 4096 的 `0.0354/0.0313`；
单层速度不是端到端速度或视觉质量保证。

相同提示词、seed、256px 有序参考图，每条路线先 prepare、2 步预热，
再作两次**相同编辑条件缓存命中**的 40 步请求；每轮混合实际调用
`39×29=1131` 次 Core ML FFN，output copy 为 0。请求墙钟：

| 参考数 | GPU（两轮，秒） | 4096 W8A8（两轮，秒） | 6144 W8A8（两轮，秒） | 6144/GPU 均值加速 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 43.894/43.925 | 36.325/36.315 | 32.352/32.370 | 1.357× |
| 2 | 44.733/44.777 | 37.159/37.176 | 33.236/33.187 | 1.348× |
| 3 | 45.581/45.612 | 38.042/38.061 | 34.111/34.054 | 1.338× |

每条路线两轮 PNG 逐字节相同。相对 GPU，6144 的单图 RGB correlation
`0.99833`、RMSE `0.01903`；双图 `0.92777`、RMSE `0.11320`，
两把茶壶均在但构图偏移明显；三图 `0.98257`、RMSE `0.05755`，
