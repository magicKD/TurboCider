## 同库、同窗口、同六步条件

沿用原 BF16 Qwen 2.1 encoder / DiT / VAE 和
`build/qwen512-student-prefix-20261017/libturbocider.dylib`，库 SHA256
`b876fc7190cd63259601639ebf1c81c544f6bdc5c17e7f50d1e5bf9db106acff`。
不需要改写 native pin、关闭模型校验或重新导出 ANE 模型。

顺序为 r256/joint → r128/original → r128/joint → r256/joint。
每条路线独立进程、11请求，共44完整 PNG；首项、首次编辑和 populate 不计入 hit
分母。生成与红茶壶编辑沿用相同提示词、seed73/74、同参考及512参考预处理，
输出512²、6 sampler更新、227 adapter bindings、strength1/inference_time。
没有 ANE、DiT residual cache、末步 FFN 复用或权重合并；测量中不并行 build/test。

计分为 conditioning 热态；编辑计分还区分 snapshot-off 和真正 prefix hit。
r128/ref512 走现有 public GPU request opt-in，不借 r256 的 resize diagnostic。
rank 才是跨模型比较的变化；算术两臂另行保留，不拼接最快 phase。

## 观察到的收益不大

| 同为 joint GPU | r256 前窗 / s | r128 / s | r256 后窗 / s | 对两控制的名义减少 |
| --- | ---: | ---: | ---: | --- |
| 文生图，3个warm请求中位数 | 7.7831 | 7.4880 | 7.7837 | 3.79–3.80% |
| 前缀命中编辑，seed73 | 7.9408 | 7.6410 | 7.9017 | 3.30–3.78% |
| 前缀命中编辑，seed74 | 7.8968 | 7.6219 | 7.8758 | 3.22–3.48% |

两个 r256 窗口的全部11张对应 PNG 均 RGBA 逐像素相同。
这提高了本次 source/输入一致性的证据，但不是交错 ABBA 或长期独立窗口资格。
每个编辑 seed 每臂仅一项 hit，不能把小样本范围写作置信区间。

r128 原始算术的生成热请求为7.728/7.739/7.699秒，编辑 hit 为7.877/7.891秒；
joint 为7.479/7.488/7.502秒和7.641/7.622秒。相对自己的 snapshot-off 控制，
r128 joint 前缀复用减少约13–14%，本批两 seed RGBA 完全相同；不能把该前缀收益
再乘到跨 rank 的3–4%上。参数数量/文件减半，没有带来推理耗时减半。

不授予任意文本、身份、多参考和材质保真资格。r128 内 original→joint 的差异另存
`precision-comparison.json`，不把它与 rank 近似混合。

## 内存、负载、保留决策

四条路线 memory sampling 均 complete（100ms、max gap500ms）。process-tree峰值：
r256前窗32,061,217,784 bytes，r128原始31,687,777,032，r128 joint31,887,416,168，
r256后窗31,666,363,072。单文件更小不等于整个运行峰值同比下降，观察窗口和文件/
driver状态会影响峰值，不能相加 MLX 与 process 统计。

前三窗口系统 swap-out=0，r256后窗589,824 bytes；不归因给某个 adapter。
所有 continuous CPU-load 检查均失败，保持 `qualification_passed=false`，
未停止用户 ComfyUI 进程，未授予物理 GPU 独占或能耗资格。

r128 保留为显式可选来源，不替换用户 r256、不改默认/App，也不把约3–4%说成
重大 kernel 突破。主要 pipeline 成本仍不随 LoRA rank 减半；下一轮优先调查
原模型图构建/提交与合适的 GPU/ANE 分工，而不是继续任意削减模型或采样步骤。
完整优化目标保持 active。
