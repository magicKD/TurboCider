# Qwen Image 2.1：1024² W8A8 GPU/Core ML 诊断

以下均为本机显式诊断生成器结果，不是生产 Session
质量验收或物理 ANE 驻留证明；`CPU_AND_NE` 仅指定 Core ML 计算设备
策略。生产 CLI 的 Qwen 混合路线仍只接受 512² 文生图的 FP16 manifest。

从 BF16 checkpoint 的 1024²／5 步狐狸纯 GPU 请求，在第 2 个去噪步
复用真实 prefix KV，采集全部 32 层 `[4096,4096]` 的 FFN 输入。
由这些输入独立校准、导出并编译 4096 行 W8A8 图：ANE 计算 4096
个 FFN hidden channels，GPU 计算剩余 8192 个，保持原来的并行
hidden-dimension 切分；未把 512² 的 1024 行模型填充后冒充 1024²。
每组结果均使用同一模型 checkpoint、prompt、seed、尺寸与步数
配对；输入对照器逐项核验 text、initial、sigmas 一致。图像与报告
位于忽略的 `results/qwen21/qwen21-w8a8-fox-*-1024-{5,40}*` 及
`results/qwen21/qwen21-w8a8-teapot-{gpu,hybrid}-1024-40*`。

在**校准输入**上的 block 0 单层 W8A8 Core ML C ABI 测试：ANE 分支
相对 BF16 rRMSE `0.02384`，合并 BF16 GPU 后缀后完整 FFN rRMSE
`0.00870`，Core ML prediction 中位 `27.75 ms`。这不是 held-out
单层精度，也不能证明实际 ANE 芯片执行。
同一 block 0 输入上的源包 `CPU_ONLY` 对 `CPU_AND_NE` 输出 rRMSE
`0.01989`，分别对 BF16 为 `0.02272` 和 `0.02384`：此例没有早期
失败图出现的约 0.91 级 CPU／NE 差异，但公开 API 仍无法证明物理
ANE 驻留，也不能凭一个校准层证明 32 层一致。

| 1024² 路线 | 步数 | 后续步中位数 | 含首步去噪加速比 | 首次完整请求 | RGB correlation |
| --- | ---: | ---: | ---: | ---: | ---: |
| 纯 BF16 GPU | 5 | 4.710 s | 基线 | 26.906 s | — |
| W8A8 Core ML + BF16 GPU 后缀，32/32 | 5 | 3.890 s（1.211×） | 1.153× | 37.461 s | 0.99877 |
| W8A8 Core ML + W8A16 GPU 后缀，32/32 | 5 | 4.338 s（1.086×） | 1.060× | 34.564 s | 0.99896 |
| 纯 BF16 GPU | 40 | 4.702 s | 基线 | 192.442 s | — |
| W8A8 Core ML + BF16 GPU 后缀，32/32 | 40 | 3.901 s（1.205×） | 1.199× | 169.381 s | 0.97962 |
| 茶壶＋盆栽，纯 BF16 GPU（seed 17） | 40 | 4.703 s | 基线 | 192.483 s | — |
| 茶壶＋盆栽，W8A8＋BF16 后缀，32/32 | 40 | 3.906 s（1.204×） | 1.197× | 169.530 s | 0.91809 |

5 步的混合路线共 128 次，每个 40 步混合请求共 1248 次 Core ML FFN 调用，
output copy 为 0；这对应解码时 32/32 层 W8A8 + GPU 并行。
40 步的 Core ML prediction API 后续步中位 `0.942 s`、平均每层
`29.44 ms`。API 时间与 GPU 工作重叠，不能从总步时直接相减。
本次 W8A16 GPU 后缀较 BF16 后缀慢，因而保留 BF16 后缀为当前
较快的显式诊断候选；W8A16 目前只测了 5 步，不外推其 40 步表现。

5 步两张狐狸图均明显模糊，不用于画质验收。40 步两张图均清晰，
主体与构图接近，眼睛、耳朵和毛发存在差异；latent rRMSE
`0.10794`、RGB correlation `0.97962`。就此 prompt/seed 目视仍可接受，
校准与狐狸出图使用同一 prompt（步数不同）；为初步检查迁移，
又使用未参与校准的陶瓷茶壶＋盆栽提示词、seed 17 跑了另一组 40 步
GPU／混合匹配输入。两图都清晰，有茶壶、盆栽、木桌与柔和日光，
但混合图的壶嘴和把手**左右对调**：RGB correlation `0.91809`、
latent rRMSE `0.30731`，明显不能称为构图忠实。若只要求合理生图，
此例目视可接受；若图像编辑需要固定朝向或参考物体细节，则本例
不足以通过验收。仍需更多独立题材/seed、1–3 参考图编辑及重复
warm Session 对照，才能谈生产质量与速度门槛。
5 步首次完整混合请求反而比纯 GPU 慢；40 步首次完整请求单轮更快，
均不能当成 resident warm Session 加速比。

校准目录 `qwen21-w8a8-calibration-1024-fox-5/` 约 2.0 GiB，完整
源 `.mlpackage` 与编译缓存各约 1.5 GiB；这些本地实验产物不入 Git。
导出器仅接受配对行数的真实校准文件（1024／4096 两种固定形状），
诊断混合生成的 1024² 路线暂限无参考图文生图，避免把未验证的
1024² 编辑错误地宣称已经加速。
