## 首次算法对照结论（2026-10-17）

四轮请求中位数 **24.503 秒**，当前 W8A8 为 **22.740 秒**；耗时变化：增加 1.763 秒（7.75%）。三个提示词中 **3/3** 的 RGB RMSE 低于当前 W8A8；合并像素 RMSE 为 **2.695481**，相对当前 W8A8 **降低 40.51%**。

本轮判断：**有效的保真选项，代价是额外耗时。** 三个评估样本都更接近本轮参考，合并像素 RMSE 降低 40.51%；每次请求中位数增加 1.763 秒（7.75%）。以速度为首要目标时仍应保留当前 W8A8；更看重接近浮点参考时，这一固定组合值得保留。

单独 SmoothQuant 的结果较差，叠加旋转后却明显改善，说明两者存在交互作用，收益不能简单相加。缩放后再旋转有机会同时缓解激活与权重分布的不均衡；本轮最终图像支持这一配方的效果，但没有逐层消融证明唯一的误差来源。物体样本中单独 ConvRot 更接近参考，组合优势是本次三个样本合并后的结果。

## 优化点与原理

顺序固定为先 SmoothQuant 再 ConvRot：`X′ = X S⁻¹ R`、`W′ = W S R`，因此 `X′W′ᵀ = XWᵀ`。缩放和旋转通常不可交换；两侧必须使用匹配的次序。

SmoothQuant 直接复用单独方案的同一份冻结校准 profile、alpha=0.5 与 [1/16,16] 缩放范围；ConvRot 复用 regular H256/H64。缩放及旋转采用 FP32，变换完成后激活转 FP16，再进入原 Cider 真正的 W8A8 运算。权重侧将缩放和旋转一次性写入持久缓存。在线缩放、旋转及其临时缓冲全部计入耗时。

组合的动机是先平衡通道幅度，再分散残余尖峰。但缩放可能让权重更难量化，旋转也可能使某些分布产生更大峰值，所以不能把两个单项的收益相加。本实验没有另外调整组合方案的校准参数。原理参考 [SmoothQuant](https://arxiv.org/abs/2211.10438) 与 [ConvRot](https://arxiv.org/abs/2512.03673)。

## 对照条件

固定 Apple M5 Pro、精确 24 GiB（25,769,803,776 字节）、无 LoRA、512×512 文生图、40 步。所有评估组均使用 layer-streamed text/DiT、component_staged、原有 GPU＋ANE 分区、Q/K norm RoPE 融合和 DBCache fast；文本编码器与 VAE 的实现及精度不变。

本节时间全部来自 2026-10-17 重新运行的接电请求，不引用此前计时。每两秒采样电源状态，整次请求 ExternalConnected=true；没有主动更改系统电源设置。

正式耗时使用狐狸、seed=42。四轮平衡顺序为 A/B/D/C、B/C/A/D、C/D/B/A、D/A/C/B（A=当前 W8A8，B=ConvRot，C=SmoothQuant，D=组合），每个方法各处于一次每个位置，轮内前后相邻关系平衡。每个请求使用独立进程，全部命中预先准备的离线缓存；没有清空操作系统文件缓存。正式计时期间不并行运行本任务的编译或其他推理，桌面背景程序保持正常运行。

计时为 request_wall_including_export，包含模型加载、源 SHA 验证、ANE 准备、文本编码、DiT、VAE 及 PNG 导出，排除进程启动及 engine 创建。首次缓存生成另列。样本数为 4，不能将小于波动的差异认定为稳定加速。

图像参考也在本轮重新生成：仅把 GPU DiT 恢复为原浮点路径，保持相同 ANE、Q/K 融合、DBCache fast、提示词和 seed。它是“GPU 浮点＋固定量化 ANE”参考，不是全模型 BF16。RGB RMSE 使用未经色彩转换的 0–255 RGB 像素；越低表示更接近该参考，不等同于感知质量或语义准确率。另列相对当前 W8A8 的偏差，避免把“发生变化”误写成“精度改善”。

## 实际耗时

| 配置 | 四次整次请求秒数 | 中位数 | Denoise 中位数 | MLX 峰值中位数 |
| --- | --- | ---: | ---: | ---: |
| 当前 W8A8＋离线缓存 | 22.513 / 22.917 / 22.770 / 22.711 | 22.740 秒 | 12.517 秒 | 5.429 GiB |
| SmoothQuant＋ConvRot | 27.937 / 24.762 / 24.243 / 24.233 | 24.503 秒 | 14.136 秒 | 5.429 GiB |

同一轮中，本方案比基线增加的秒数为 +5.424 / +1.845 / +1.473 / +1.523。首轮至末轮变化、加载阶段与系统背景均可能影响端到端差值，不用单次结果推导硬件吞吐。

缓存读取累计计时中位数：当前 W8A8 1.611 秒，本方案 1.559 秒；这段计时包含加载和求值等待，不能直接等同 SSD 物理 I/O 时间。

首次空缓存请求 **36.340 秒**，量化、变换及写入累计 **12.741 秒**，写入 392 个数据文件、**10.89494 GiB**。首次生成只测一次，属于准备成本记录，不并入命中缓存的中位数。

持久缓存只省去了权重侧的离线缩放/旋转与量化；每一步的新激活仍需在线变换。本实现将这些变换放在 Cider 激活量化内核之前，包含额外 FP32 运算、数据缓冲与 kernel 调度，没有融合进 Cider 的 quantize_per_token。因而本轮速度结论针对这个实际实现，不能当成算法的理论最快速度。去噪阶段的中位数也高于当前基线，额外成本并非全部来自首次磁盘缓存读取。

## 客户端开启与对比

1. 选择 Qwen Image 2.1、512×512 文生图、20–40 步，无 LoRA；开启分阶段加载和固定 W8A8 ANE 分区。
2. 在「推理加速与准备」开启「DiT W8A8＋离线缓存」。
3. 新增「SmoothQuant＋ConvRot（DiT 保真选项）」默认关闭。关闭时仍使用当前 W8A8；开启后使用组合方案。只切换该项，保持提示词、种子、步数及 DBCache 档位一致。
4. 两套缓存互相独立。组合方案第一次使用额外生成约 11 GiB 缓存；比较后续请求时，应先各完成一次生成。文本编码器、VAE 和原冻结 ANE 分区不变。

草稿、历史记录和 v1/v2 请求都保留独立开关。条件不符合时不能开启；已保存的不适用开关可以关闭，执行时也会拒绝无效组合。客户端不改变既有 W8A8 开关的默认值，不会替用户切换硬件或采样配置。

API：v1 顶层 `qwen21_dit_smoothquant_convrot: true`；v2 放在 `execution`。必须同时启用 `qwen21_dit_w8a8: true`。未指定或 false 保持当前 W8A8 配方。

## 生产接入

- 沿用精确 Apple M5 Pro / 24 GiB 门槛；普通 M5、M5 Max、其他内存容量均不放行。还要求无 LoRA、单张 512×512 文生图、20–40 步、MLX、component_staged、流式 text/DiT、固定 W8A8 ANE 6144 通道分区；常驻、纯 GPU、Runtime ANE、参考图、提示词增强不支持。
- 392 个投影、1,925,440 个 FP16 输入逆缩放系数随原生库内置。3.67 MiB 系数不依赖实验路径，不在用户机器上重新校准；模型源 SHA 不匹配时拒绝组合方案。
- 校准参数：alpha=0.5、缩放截断 [1/16,16]。三个独立校准提示词与 seed、输入文件 SHA、投影索引保存在 [校准索引](../../../native/models/qwen21/calibration/sq_convrot_v1.json)。评估的狐狸、文字、物体样本没有参与校准。
- 构建时验证系数 payload SHA、通道覆盖、有限正数范围；构建身份同时覆盖系数和索引。持久缓存以新配方和系数 SHA 隔离，命中时还逐通道核对逆缩放系数。
- 每个请求拥有缓存对象和取消回调，编译函数通过权重参数显式区分变换；没有进程级模式变量。沿用逐层释放、加锁和原子发布，不延长权重到 VAE 阶段。

源码：[量化与缓存](../../../native/models/qwen21/cider_w8a8.cpp)、[旋转](../../../native/models/qwen21/smoothquant_convrot.hpp)、[硬件与请求条件](../../../native/models/qwen21/memory_policy.hpp)、[开关界面](../../../apps/macos/AccelerationView.swift)。
