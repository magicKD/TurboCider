# Qwen-Image-2.1 base DBCache 实验（2026-09-27）

## 实现与准入

参考 `../references/stable-diffusion.cpp/src/runtime/cache_dit.hpp` 的
前段残差变化／中段残差复用方案；没有复制其 GGML 张量或跨条件缓存。
TurboCider 的实现位于 `native/models/qwen21/transformer.cpp`，只针对
一次采样内已经建立 prefix-KV 的 decode 步。首步 prefill 不使用 DBCache；
每个请求开始清空上一次的前段残差和中段残差，故即使 resident Session
跨请求命中前缀 K/V，也不会跨请求复用 DBCache。

默认前 8 层完整计算、后 0 层完整计算，中间 24 层的**合并输出减输入**
保留为独立且已 materialize 的 MLX 张量。每步比较当前前 8 层相对首层
输入的残差与上一步的相对 L1 变化，低于阈值才跳过中间 24 层。
为减少长串漂移，前 8 步预热、最多连续跳过 2 步且最后一步必定完整
计算；跳过时当前前段残差仍会更新。Core ML 的 output backing 不存入
跨步缓存。该路径不与既有末步 FFN 复用叠加。

仅显式设置 `TURBOCIDER_QWEN21_DBCACHE_DIAGNOSTIC=1`，并在请求里允许
近似，才准入 20–40 步、512×512 的 base GPU 或 GPU/ANE 文生图、
以及 1–3 张参考图的编辑。后续另扩展到 768×512／512×768 的
base GPU，以及同时显式开启
`TURBOCIDER_QWEN21_RECT_W8A8_DIAGNOSTIC=1` 的矩形 hybrid；
仍只支持原尺寸编辑参考图，其性能和观感见
[矩形 W8A8 复用实验](qwen21-rectangular-w8a8-2026-09-27.md)。可通过
`TURBOCIDER_QWEN21_DBCACHE_THRESHOLD=0.08` 调整阈值，必须是
`(0, 0.5]` 的有限数；默认 `0.08`。该开关是诊断路径，尚非默认推荐。
可选 `TURBOCIDER_QWEN21_DBCACHE_MAX_CONSECUTIVE=1...8` 调整最多
连续跳过的 decode 步，默认 `2`；仅允许 DBCache 显式开启时设置。
更大的上限可以减少重复计算，但放大跨步残差漂移，必须另做图片观感
验收，不能自动用于一般请求。
报告中 `qwen21_dbcache.cached_steps` 与 `saved_middle_blocks` 为
**本请求**计数；对 hybrid 还校验实际 Core ML 调用数，矩形时
每个省下的中间层对应两次 Core ML 预测。

## 第一组 512²、20 步文生图（GPU，茶壶）

`qwen21-session-probe` 同模型、prompt、seed 42、已加载且同样完成完整
20 步预热的 resident Session；各测试均仅报告一次 warm 测量，尚无重复
运行置信区间。PNG 存在忽略目录之外的临时目录，不进入 Git。

| 候选 | warm 墙钟 | 去噪时间 | 跳过 decode 步／省去 block | 相对精确 GPU PNG |
| --- | ---: | ---: | ---: | --- |
| BF16 GPU 基线 | 21.936 s | 21.321 s | 0／0 | 原图 |
| DBCache 阈值 0.08 | 21.988 s | 21.369 s | 0／0 | SHA-256 完全一致 |
| DBCache 阈值 0.25 | 15.590 s | 14.980 s | 8／192 | 与 0.50 输出逐像素相同 |
| DBCache 阈值 0.50 | 15.575 s | 14.984 s | 8／192 | RGB RMSE 4.95/255，correlation 0.99739 |

阈值 0.50 的这张茶壶图片肉眼看主体、构图与材质一致，纹理明暗有
轻微不同；warm 整体速度相对 GPU 基线约 `1.41×`。这只证明一组
同输入样本，编辑中的对象/文字/贴纸保真和其它种子仍未验证，不能
据此把 0.50 设为默认推荐。0.25 在此样本与 0.50 的决策完全一致，
但其他负载不保证相同；0.08 则没有真正加速。

数值指标用于发现异常并辅助复核。在肉眼差异可接受的前提下，
优先比较同条件请求的实际墙钟时间。

## 40 步三图编辑（GPU，512px 参考）

同 prompt、seed 17、三张有序参考图，各 Session 单独完成完整 40 步
预热，再测一次 prompt／参考编码命中的请求。比较器已核对 text、
initial noise、三张 reference tensors 逐字节相同；因此此处是同输入
配对，不含 cold start。

| 路线 | warm 请求／去噪 | 跳过步数／中间层 | 对精确 GPU 的 RGB RMSE／相关系数 |
| --- | ---: | ---: | ---: |
| BF16 GPU | 52.305／51.619 s | 0／0 | 基线 |
| BF16 GPU + DBCache 0.25 | 33.503／32.810 s（1.561×） | 21／504 | 4.02/255／0.99872 |

两张 PNG 并排肉眼看米色壶居左、蓝壶居右、橙龙贴纸居中；壶嘴、
把手、盖钮、龙的眼睛与白色贴纸轮廓均保留。差别集中在壶身细纹、
木桌光影等局部，不是明显的对象丢失。不过只有单种子、一次 warm
配对，主观可接受不等同所有编辑 prompt 都成功。

进一步保持阈值 `0.25`、预热 `8` 步和其它条件不变，单独把最多连续
跳过数从 `2` 调至 `4`，对同一三图 40 步请求再次配对。下表两种
GPU/ANE 均指同一 6144-channel W8A8 manifest；候选用重新链接原生
库后的 Session 探针，分别验证 text/noise/reference tensors 一致。

| 路线 | 无缓存 → max=2 → max=4 墙钟 | max=4 对相同路线无缓存 | max=4 跳步／Core ML 请求调用 | max=4 相对无缓存 RGB |
| --- | ---: | ---: | ---: | ---: |
| BF16 GPU | 52.305 → 33.503 → 29.889 s | 1.750× | 25／不适用 | RMSE 7.81/255，correlation 0.99513 |
| W8A8 hybrid | 39.497 → 26.493 → 23.418 s | 1.687× | 25／1248→648 | RMSE 8.55/255，correlation 0.99438 |

`max=4` 共少计算 `25 × 24 = 600` 个中间 FFN 层，hybrid 双方
均零 Core ML 失败。人工并排检查：两把茶壶及居中龙贴纸的主体均
保留，贴纸的眼睛、嘴和白边仍可辨；蓝壶把手、陶瓷细纹和桌面阴影
与基线有更明显差异，但在这一种子／提示词下仍属可接受的构图级
近似。这是单次配对而非 ABBA 稳定性结论；`max=4` 暂不设为默认。

同一三图工作负载把连续上限再调到 `8`，得到 GPU `27.131 s`
（相对无缓存 GPU `1.928×`），hybrid `21.375 s`（相对无缓存 hybrid
`1.848×`，比同一次 GPU 候选快 `1.269×`）。两边各跳过 28 步、
省去 672 个中间层；hybrid 每请求 Core ML 预测数 `1248 → 576`、
零失败。双方与各自基线 text/noise/三参考张量逐字节相同；RGB
RMSE 分别为 `11.16/255` 和 `10.73/255`。人工查看仍能辨认米色壶、
蓝壶和龙贴纸的双眼及白边，蓝壶把手与桌面阴影变化更大；该单样本
可以接受构图级差异，但不能证明贴纸文字、小物体或所有编辑任务
均可接受 `max=8`。严格实测的最快这组配置仍保留为诊断选项。

另外 40 步茶壶文生图的同配置 hybrid warm 请求为 `15.227 s`，
相对先前无缓存 hybrid 的 `30.544 s` 为约 `2.006×`；同为 28 步跳过、
请求调用 `1248 → 576`。并排 PNG 看壶嘴、把手、壶盖、盘子保持；
旧基线没有保存 text/noise dump，比较器仅核对了 metadata，不能将
此组当作严格逐字节同输入验证，后续需要重跑匹配的完整基线。

另用**雪地松树旁的赤狐**作为不同文生图提示做 40 步配对，仍为
阈值 0.25／连续上限 8。此次 GPU 与 hybrid 各自完整预热后单次
warm 测量，均核对 text/noise 张量逐字节一致：

| 路线 | 无缓存 → DBCache 墙钟 | 本请求 Core ML 预测 | RGB RMSE／相关系数 |
| --- | ---: | ---: | ---: |
| BF16 GPU | 43.187 → 20.988 s（2.058×） | 不适用 | 15.78/255／0.97506 |
| W8A8 hybrid | 30.385 → 15.217 s（1.997×） | 1248→576 | 15.61/255／0.97770 |

两组各跳过 28 步且 hybrid 零运行失败；缓存 hybrid 相对缓存 GPU
墙钟约 1.379×。肉眼检查都仍是坐在雪地松树前的赤狐，前腿、脸型、
尾巴毛发与积雪纹理变化明显但主体、姿态和场景没丢；这是「观感
近似可接受」而非要求像素精确的例子。单 seed 不足以决定其它动物、
文字或小参考物体的安全上限。

补充 `max=8`、阈值 0.25 的 **20 步一／二图编辑**，参考图片同样
缩至 512px。独立 Session 完整 20 步预热，每组仅一次 warm 配对；
比较器核对文本、noise 和每张有序参考图张量逐字节一致：

| 输入 | 无缓存 hybrid → DBCache hybrid | 比值 | 跳过步数／本请求 Core ML 调用 | RGB RMSE／相关系数 |
| --- | ---: | ---: | ---: | ---: |
| 一图红壶 | 17.726 → 11.958 s | 1.482× | 10／608→368 | 5.04/255／0.99809 |
| 两图米壶+蓝壶 | 19.796 → 13.758 s | 1.439× | 10／608→368 | 6.09/255／0.99698 |

两组零运行失败。肉眼检查一图的壶嘴、盖、把手与桌面布局接近，
但无缓存基线自己没有完成「哑光红」编辑，不能把缓存贴近基线
解释成编辑质量合格；两图米壶左、蓝壶右与两壶的把手、壶嘴仍保持，
蓝壶色调／阴影变化可见。两组仍是单 prompt、单 seed 的诊断样本。

## 40 步原尺寸 1024px 参考图（一图编辑）

把红壶参考图送入原尺寸处理，参考序列变为 **4096 tokens**；
仍是 512×512 输出。各 Session 完整 40 步预热后单次 warm 配对，
阈值 0.25、连续上限 8，GPU 与 hybrid 各自比较无 DBCache 的
同路线基线。hybrid 同时需要已有的
`TURBOCIDER_QWEN21_FULL_REF_W8A8_DIAGNOSTIC=1` 门禁；首步仍
完整 GPU prefill，不宣称首次生成加速。

| 路线 | 无缓存 → DBCache 墙钟 | 跳过步数／本请求 Core ML 调用 | RGB RMSE／相关系数 |
| --- | ---: | ---: | ---: |
| BF16 GPU | 55.204 → 29.174 s（1.892×） | 28／不适用 | 5.31/255／0.99787 |
| W8A8 hybrid | 42.443 → 23.417 s（1.813×） | 28／1248→576 | 5.71/255／0.99762 |

每组比较器都验证 text、initial noise、原尺寸参考 latent 逐字节一致；
hybrid 双方无 Core ML 失败。候选 hybrid 相对同样开缓存的 GPU
墙钟约 `1.246×`。两组 PNG 并排查看壶嘴、盖钮、把手、壶身细纹
基本保留；但两个无缓存基线也未将茶壶变成提示要求的哑光红壶，
所以此结果只能证实缓存没有明显恶化当前输出，不能证明编辑任务成功。
原尺寸 2–3 图的首步成本仍需另行验收。

## 40 步原尺寸两图编辑：GPU 与 GPU/ANE 四路同输入

512×512 输出、米壶／蓝壶两张按 1024px 编码的参考图，seed 17，
相同编辑提示。四个独立 resident Session 各自完整 40 步预热后，
仅取一次 prompt／参考图条件编码命中的 warm 请求；DBCache 阈值
`0.25`、连续上限 `8`。跨四路的 text、initial noise、两张有序
reference tensors 均经比较器逐字节验证相同。墙钟包括 VAE/PNG 和
少量张量 dump，不包含首次权重及 Core ML 加载。

| 执行路线 | 无缓存 → DBCache warm 墙钟 | 同路线缓存加速 | 跳步／请求内 Core ML 调用 |
| --- | ---: | ---: | ---: |
| BF16 GPU | 68.414 → 38.224 s | 1.790× | 28／不适用 |
| W8A8 6144-channel hybrid | 57.308 → 32.797 s | 1.747× | 28／1248→576 |

缓存 hybrid 比缓存 GPU 快 `1.165×`；两路无缓存 GPU/hybrid 为
`1.194×`。每路缓存都省去 `28 × 24 = 672` 个中间 block，hybrid
Core ML 预测数正好减少 672、无运行失败且 checkpoint SHA 验证通过。
相对本路线无缓存基线，GPU 缓存图 RGB RMSE `8.84/255`、相关
`0.99287`；hybrid 缓存图为 `6.75/255`、相关 `0.99618`。
**这些像素数值不作为质量阈值**：并排查看四图，米壶左、蓝壶右，
壶嘴、盖钮、把手和桌面布局都保留；蓝壶透明感和阴影、米壶釉面
纹理有差异。按主体与指令是否保留的宽松肉眼标准，此编辑样本可接受。

新增 `qwen21_compare_sessions.py` 的 full-reference GPU→hybrid
比较门禁：核对原尺寸参考图、双方相同的缓存策略、已验证 manifest、
每请求 `39 × 32 - saved_middle_blocks` 次 Core ML 预测，再验证
同输入张量。另以**镜像顺序**重复四条独立 Session：首轮为无缓存
GPU、缓存 GPU、无缓存 hybrid、缓存 hybrid；次轮顺序反过来。
每路都完整 40 步预热并测一次 warm 请求，第二轮输入张量逐字节
一致、调用预算／零 Core ML 失败及生命周期检查均通过：

| 路线 | 第一轮／第二轮 warm 墙钟 |
| --- | ---: |
| 无缓存 GPU | 68.414／68.169 s |
| 缓存 GPU | 38.224／38.388 s |
| 无缓存 hybrid | 57.308／57.261 s |
| 缓存 hybrid | 32.797／32.778 s |

两轮的缓存收益：GPU `1.790×／1.776×`，hybrid
`1.747×／1.747×`；缓存 hybrid 对缓存 GPU 分别
`1.165×／1.171×`。同一配置相同 seed 的两轮 PNG 与输入比较
结果一致。这里只验证了一个提示与 seed 的镜像顺序小样本，
没有严格材质／贴纸编辑的质量门禁，不能保证 hybrid 恒比 GPU 快，
也不能将 resident 时间外推到 `component_staged` 冷请求。

合入 `dev-verify` 的 Core ML 输出拷贝修正并重新构建原生库、探针后，
相同两图 40 步缓存 hybrid 再做一次完整预热／warm 请求得到
`32.823 s`，此前两次为 `32.797／32.778 s`。请求内调用仍为
`576`、零失败；PNG SHA-256 与合并前完全一致，缓存 GPU 对照
的输入张量比较仍相同。在**这一工作负载**没有观测到功能或墙钟
退化，不能据此推断所有模型、画布或首次 Core ML 编译都无回退。

继续合入 `feat/stream` 并重建原生库／Session 探针后，同请求
缓存 hybrid `32.815 s`、缓存 GPU `38.383 s`，同输入约
`1.170×`。两张 PNG 分别与合并前对应路线的 PNG SHA-256 一致；
hybrid 仍跳过 28 步、请求内 576 次 Core ML 预测、零运行失败。
此检查只覆盖同一 base 两原尺寸参考图编辑的 resident warm 路线。

## 40 步原尺寸三图编辑：首步局部注意力叠加缓存

同一三图 prompt、seed 17、512² 输出，但每张参考按 **1024px**
原尺寸编码。hybrid 为已有 checkpoint-SHA 验证的 6144-channel
W8A8 manifest；三个独立 Session 各自完成完整 40 步预热后仅测
一次 warm 请求，text/noise/三张按顺序排列的 reference tensors
逐字节相同，均不包括冷加载。

| 配置 | 请求墙钟 | 相对无缓存 hybrid | 跳过步／每请求 Core ML 预测 | 相对无缓存 RGB |
| --- | ---: | ---: | ---: | ---: |
| 无缓存 hybrid、准确首步注意力 | 71.692 s | 基线 | 0／1248 | 原图 |
| DBCache 0.25，连续上限 8 | 43.902 s | 1.633× | 28／576 | RMSE 8.84/255，correlation 0.99410 |
| 再叠加后 16 层 reference-local 首步注意力 | 41.650 s | 1.721× | 28／576 | RMSE 15.68/255，correlation 0.98108 |

两条缓存路径均零 Core ML 运行失败、保存 672 个中间层计算；
第三条相对单独 DBCache 又快约 1.054×。比较器已核对缓存后真实
调用从 1248 降为 576。三个 PNG 肉眼仍是米壶左／蓝壶右／橙龙
贴纸居中，茶壶壶嘴、盖钮、把手、贴纸双眼及白边可辨。叠加局部
注意力时贴纸脸型、白边和桌面阴影变化更明显，但这个提示词的
主体与摆放仍符合预期；不要求逐像素高度接近。它不证明其它
prompt、小字、细小主体或严格材质编辑都能接受，也没有多种子、
交错重复测试，因此速度最快的叠加方案保持显式诊断而非默认。
首步长序列 prefill 未被 DBCache 跳过；这是原尺寸三图相对缩图
三图增益较小的关键限制，不能把两个参考尺寸的计时混为一谈。

另在第三条上显式叠加首步最后一层 target-only，单次 warm 请求
`41.650 → 41.435 s`；输出 PNG 的 SHA-256 与第三条完全相同。
原尺寸参考图的首步 FFN 仍在 GPU，故该开关不减少 Core ML 预测，
每请求仍为 576 次；0.2 s 的单次差别不足以证明真实加速，
不纳入最快推荐。Session 探针取消／GPU 切换／卸载通过。

再将上述无缓存与 DBCache＋reference-local 两路换为相同提示和三张
参考图的 seed 29，双方完整 40 步预热、单次 warm 测量：
`71.409 → 41.708 s`（`1.712×`），各输入张量逐字节相同。
仍跳过 28 步、调用数 `1248 → 576`、零失败；相对无缓存图像
RGB RMSE `14.41/255`、correlation `0.98403`。人工看两个茶壶
分列左右、贴纸居中，眼睛、壶把和壶嘴均保留；壶身纹理、贴纸
脸型以及桌面光影有所变化。本项目的验收优先看上述主体和编辑
意图而非像素指标，此样本可接受。现在有两个 seed，但仍是同一
提示词和同一组参考图，未测交错顺序的重复性或其它任务成功率。

相同三图、40 步的 6144-channel W8A8 hybrid 对照：基线 warm
墙钟／去噪 `39.497/38.839 s`，DBCache 0.25 为 `26.493/25.842 s`
（`1.491×`）。两边 text/noise/三张参考图输入张量逐字节相同；
候选跳过 21 步、504 个中间 FFN 层，Core ML 请求调用 `1248 → 744`，
两边零运行失败。相对相同 hybrid 基线 RGB RMSE `3.71/255`、
correlation `0.99895`。并排查看图片，双壶、龙的双眼／白边与原有
构图都保留，只有局部陶瓷纹理和光影变化；不能由单样本推出
普遍画质和速度保证，也不证明实际全程 ANE 驻留。

## 同输入 20 步文生图的 GPU／W8A8 GPU+ANE 对比

使用既有 checkpoint-SHA 验证、32 层、1024 行、6144-channel W8A8
Core ML manifest，两个 hybrid Session 分别完整预热 20 步；输入 prompt、
seed 42 与前述纯 GPU 茶壶相同。下表仅为各自独立 resident Session
的一次 warm 测量，未证明物理 ANE 驻留：

| 路线 | wall / denoise | 相对同路线无 DBCache | 本请求 Core ML 次数 |
| --- | ---: | ---: | ---: |
| BF16 GPU | 21.936／21.321 s | 基线 | 0 |
| BF16 GPU + DBCache 0.25 | 15.590／14.980 s | 1.41× | 0 |
| W8A8 hybrid | 15.826／15.235 s | 基线 | 608 |
| W8A8 hybrid + DBCache 0.25 | 11.528／10.940 s | 1.37× | 416 |

DBCache-hybrid 省掉 `8 × 24 = 192` 次 FFN Core ML 调用，运行失败数
为 0。hybrid 两张 PNG 的 RGB RMSE `4.18/255`、correlation
`0.99823`；目视主体/构图保持，局部陶瓷纹理变化。这一配对验证的是
缓存可用于既有 hybrid 路线，不代表跨工作负载有固定的倍速。

同 manifest 的 40 步文生图单次 warm 配对：hybrid 基线墙钟／去噪
`30.544/29.954 s`，阈值 `0.25` 候选 `19.272/18.678 s`（墙钟约
`1.58×`）。候选跳过 21 步、少做 `504` 层 FFN，Core ML 请求内
调用数 `1248 → 744`，两边无运行失败。RGB RMSE `4.73/255`；
人工并排查看主体、壶嘴、把手、壶盖与盘子都保留，陶瓷斑驳纹理及
局部阴影有细微变化。仍仅为单 prompt、单 seed 和一次测量，不能
据此将此阈值开放为默认加速。

三张 512px 参考图的 20 步编辑在同一 manifest 上也完成配对：
hybrid 基线 `22.316 s`，DBCache hybrid `17.199 s`（`1.30×`），
均为缓存条件下单次 warm 墙钟。省去 192 次 Core ML FFN 调用，
两边运行错误均为 0。候选相对 hybrid 基线的 RGB RMSE
`3.79/255`、correlation `0.99892`；PNG 人工查看均保留米色壶、
蓝色壶和居中橙龙贴纸，贴纸眼睛轮廓无明显破坏。仍需 1–2 图、
40 步和 1024px 原尺寸参考等不同负载验证。
