# 按任务选择计算路径与资源可视化

测量于 2026-09-06，最终界面与回归验收于 2026-09-07 完成。

## 产品规则

“支持某模型”“能运行某操作”“分区兼容”“加速值得启用”和“芯片正在使用”是五个不同事实。

- 模型操作来自注册表；若有 `executor_operations`，它优先于宣传性 `operations`。提交时再次校验，不让旧草稿绕过能力约束。尚未开放图片输入的模型禁用图片入口，并在导入层兜底。切换任务保留已有素材。
- 自动模式按任务匹配，不能写成“优先 ANE”。512、1024 提供尺寸快捷选项，参数区说明当前任务的候选路径；生成阶段另显示运行时确认的实际路径，历史结果显示自己的路径，不随当前草稿改变。
- 自动策略允许 INT8 近似，纯 GPU 保留 BF16。手动混合维持严格行为：不兼容报错，不偷偷缩图或换操作。自动模式兼容性失败可以回退；预测中途失败不静默重跑。
- 实时整机 CPU 来自 Mach 差分计数；App 驻留内存来自 Mach task 信息，不冒充 MLX 活跃分配。整机 GPU 来自可选驱动 `PerformanceStatistics/Device Utilization %`，失败显示不可用。每两秒刷新，离开视图停止；读数包含其他 App 的负载。ANE 利用率明确未知，Core ML 调用不能证明 ANE 驻留。

## 引擎规则

`native/runtime/acceleration.hpp` 提供独立于 Apple API 与 MLX 的案例表及纯匹配函数。键包括模型、操作、宽高、步数、实际 token 区间、硬件身份、内存和分区桶。增加路线必须补对应基准与正确性证据，不能仅增加一个“支持 ANE”布尔值。

当前候选限定 M4 Pro 48 GiB、FLUX Klein 4B、resident 驻留、4 步文生图；512×512 使用 1025–1088 总 token / 1088 桶，1024×1024 使用 4097–4160 总 token / 4160 桶。图生图、多参考图、长文本、其他尺寸/步数不继承该候选。原先 256 小图也自动填充至 1088 的行为被取消；兼容不等于 padding 成本值得支付。

编码后以实际文本和图像 token 检查；prepare 与 generate 使用相同选择函数。匹配后的 Core ML manifest 还必须恰好对应案例的桶，并通过原有权重、ABI、20 分区完整性、内存预算校验。检查桶在模型加载之前进行，避免为明显不适合的请求付出加载成本。手动路线仍可探索新桶。

App 本地发现按最低输出 token 容量过滤，选最小可容纳桶；这只是预检，参考图与准确文本 token 仍由引擎最终确认。不同桶可共存，不把一个尺寸的 manifest 当成全局通用加速开关。

## 性能验证方法

`tools/native/benchmark_resolution_routes.py` 对 512 与 1024 分别比较 GPU 原路径、GPU 融合计算块、GPU + Core ML INT8。每路线两次新进程，正序/反序各一次，每进程四次请求；首轮单列，剩余共六次取暖中位数。每轮实际输出单张 PNG，核对同路线确定性及 GPU 融合与原路径 PNG 一致。INT8 与 BF16 不要求位级相等，需要单独观察质量。

1024 单独从本地原权重导出并编译 4160-token 分区；不复用容量不足的 1088 桶。导出工具为现有 `tools/coreml/export_flux2.py`。生成与基准严格串行；桌面后台负载不受控，因此小幅差异不可泛化为所有机器稳定收益。

原始数据目录：`outputs/resolution-routing/`。启动时发现已有二进制与源码注册表不一致；`untrusted-prebuild-1024-gpu/` 的样本作废，不能引用为本轮性能依据。正式基准绑定重建引擎的 SHA-256，若运行中二进制改变即退出。

## 实测结果与采用决定

| 尺寸 | GPU BF16 | GPU 融合 | GPU + Core ML INT8 | 混合相对 GPU |
|---|---:|---:|---:|---:|
| 512×512 | 5.469 秒 | 6.047 秒 | 3.566 秒 | 1.534× |
| 1024×1024 | 25.471 秒 | 35.284 秒 | 21.548 秒 | 1.182× |

以上为包含导出的暖请求中位数，每路线六次样本。512 正反两组收益分别为 1.742× / 1.345×；1024 为 1.236× / 1.182×。两组方向一致，因此分别加入案例表。融合路线本轮没有收益，自动模式关闭融合；原有显式 GPU 融合开关保留供实验。不能把桌面负载波动下的这些比例视为所有机器的固定承诺。

1024 混合首轮分别为 33.359 / 23.492 秒，纯 GPU 首轮分别为 23.486 / 35.738 秒（最后一位以 JSON 为准）。冷加载和系统竞争仍明显，不能宣称单次冷任务必定更快。模型中心的准备、预热与卸载操作继续用于管理这一成本；首版没有运行后台自动调优任务。

两个尺寸都核对了 GPU 原路径与 GPU 融合 PNG 逐字节相等；每路线八张图也均有相同 SHA。GPU 与 INT8 输出分别目视检查，狐狸结构、构图和细节基本一致，未观察到明显质量退化；这只覆盖本次固定提示词与种子。

1024 的 4160 分区已编译到 App 自有缓存，和 512 的 1088 分区并存。选择尺寸时自动发现最小可容纳桶；尺寸、步数、操作或驻留变更会触发重新匹配，缺少对应桶则使用 GPU。运行中路径与历史结果分别显示，不把整机 GPU 利用率当作当前任务的独占使用量。

[机器可读测量记录](validation/task-aware-acceleration.json)。原始逐轮结果及 PNG 保存在 `outputs/resolution-routing/crossover/`。

复现：

```sh
.venv/bin/python tools/native/benchmark_resolution_routes.py --model "$MODEL" --manifest-512 "$MANIFEST_1088" --manifest-1024 "$MANIFEST_4160" --output "$OUTPUT"
.venv/bin/python tests/native/test_auto_acceleration.py --model "$MODEL" --manifest "$MANIFEST_1088" --manifest-1024 "$MANIFEST_4160" --output "$TEST_OUTPUT"
```

## 验收与额外交互修复

- Swift 行为测试覆盖模型能力、旧草稿、文本专用模型切换、图片导入限制、种子、撤销、剪贴板、原子导入、资源读数和真实步时。
- C++ 独立策略测试覆盖硬件、token 边界、512/1024 独立桶、其他步数/尺寸/操作、分阶段驻留与预算；原生契约十项通过。
- 真实模型测试通过三种 FLUX 操作、App/直接引擎 PNG 一致、取消、释放重载；服务与持久化回归通过。
- 自动路由十二项通过，包含 1024 拒绝 1088 桶、使用 4160 桶，以及两尺寸自动/显式混合输出逐字节一致。
- 最终安装包在界面中以 auto、1024、seed 42 实际生成，23.301 秒完成，确认实际桶为 4160。

额外发现：模型页自动磁盘统计把旧导出配置也带入请求，导致读取无关配置文件时所有模型按钮长期被占用。现在统计请求只使用明确的分区与缓存路径；导出配置只在明确执行导出时读取，并增加请求构造回归测试。只读统计在独立辅助进程执行，App 端 5 秒超时，CLI 自身也有 6 秒兜底，避免 App 退出后遗留统计进程；统计不占用 GPU 锁，也不设置生成 busy 状态。测试模拟无法返回的辅助进程，确认超时和按钮恢复；另验证非法 manifest 错误与跨进程 GPU 锁隔离。推理性能测试不受此 UI 修复影响。

最终模型页实测：当前外部源目录的统计仍会超时，但所有模型按钮保持可用；超时之后成功加载 4160 混合配置并卸载，App 驻留内存约 0.18 GiB。统计不可用会明确提示，不能保证所有外部文件提供方都及时响应。

最终 App 的 1024 PNG 与独立基准 PNG 逐字节相同；打包和签名校验通过。模型已卸载，Studio 保留生成结果。
