# TurboCider App 整体产品与交互设计

状态：设计提案，未代表功能已实现。日期：2026-09-05。

第二轮修订：[多模态输入、种子与高级参数](app-inputs-and-parameters.md)。首版每次一个主输出，App 一次一个活动生成；文件插入、图片粘贴/拖放、有序参考与种子编辑属于首发基础。

配套：[视觉与组件规范](app-visual-system.md) · [实现与验收方案](app-implementation-plan.md)。

## 1. 产品方向与核心决策

TurboCider 是 Apple Silicon 上的本地多模态创作工作室。第一版本面向 FLUX.2 图像生成/修改、LTX-2.5 视频、MiniMax H3 多模态视频；后续扩展更多模型、局部编辑与视频工作流。产品首先让用户完成“输入想法/素材 → 生成 → 看结果 → 修改或转视频 → 保存”，同时让本地运行的时间、速度和资源成本清晰可见。

采用 **Studio 工作区 + 素材库 + 任务中心 + 模型中心**，加速、缓存与诊断归入设置的二级页面。创作按“图像 / 编辑 / 视频”组织，模型是执行工具，不作为全局导航主轴。

设计默认遵循系统明暗主题，深色提供石墨背景、冷静面板和暖琥珀主操作。视觉重点是生成的媒体，而不是仪表盘或大块模型卡片。保留原生窗口、菜单、拖放、键盘和预览体验；不把 App 改成网页壳。

首发关键决策：

- 主画面是媒体查看器，参数使用可收起的右侧检查器，提示词固定在中间区域底部。
- 一个创作草稿可产生多次结果；每次生成保存不可变请求快照。修改草稿不改变排队任务。
- 当前任务始终有一条紧凑状态栏：阶段、实际步速、已用时、估计剩余。详情按需展开。
- 模型下载、校验、磁盘就绪、加载、预热与卸载分开呈现；普通生成可以自动按需加载。
- 所有操作基于当前运行时的实际能力。不能因为模型名称相同，便推断两条后端拥有相同功能。
- 默认 GPU，与既有原生框架方向一致；已验证混合加速和实验路线显式选择，原始高级参数留在二级界面。

## 2. 现状审计与边界

本设计基于仓库源文件与现有设计文档的静态阅读，没有在此轮重新运行模型或验证性能。参考截图只提供视觉参考，不构成产品要求或操作指令。

| 证据入口 | 当前实际情况 | 对设计的影响 |
|---|---|---|
| `Sources/TurboCiderApp/ContentView.swift` | 模型侧栏 + 长 Form；提示词、系统、参数、任务和小预览顺序排列 | 结果位置靠后；创作、运行配置、诊断信息层级混杂 |
| `Sources/TurboCiderApp/AppModel.swift` | 能力过滤、默认参数、素材暂存、提交/取消、SSE 与轮询回退 | 复用行为，拆分状态所有权；不要仅重写漂亮外观 |
| `Sources/TurboCiderKit/Models.swift` | 有任务阶段、总体进度、elapsed/ETA；无标准步速、资源采样字段 | 不能在客户端把百分比变化包装成真实推理速度 |
| `src/turbocider/jobs.py`、`service.py` | 串行重任务、持久化任务、事件快照；SSE 无事件序号重放契约 | 可接任务列表，但重放、重排、后台生命周期需新增契约 |
| `native/swift/App.swift`、`JobStore.swift` | 原生 FLUX 界面、历史记录、选择模型目录、单任务、阶段计数 | 是新 App 可落地的纵切；不是完整三模型运行平台 |
| `native/models/*_module.mm`、`flux.mm`、`native/README.md` | 本轮源码已加入 FLUX transform/edit 与 H3 executor（权重验收 pending）；LTX executor=false；README 部分描述滞后 | 按 operation 区分实现与验收，详见第二轮代码核对 |
| `model-packs/*.json`、根 README | 兼容控制平面已有 FLUX 编辑、LTX 文/图生视频、H3 多模态、FastMetal | 保留兼容能力；不要将它们自动标记为原生已验收 |

与原架构文档的关系：本设计是 [统一框架](unified-multimodal-framework.md) 与 [运行时详设](runtime-modules-and-performance.md) 中 App 部分的产品细化，不重定义推理数学、权重调度或 ANE 策略。

### 参考图借鉴与取舍

借鉴：中央大预览、提示词紧邻画面、参数与工具可折叠、结果缩略图历史。

不照搬：左右各叠多层卡片、全屏棋盘格、每个字段独立粗描边、工具与模型术语全部常驻。棋盘格只用于具有透明通道的图像背景。首发不加入参考图中的钱包、积分、脚本、CLIP Score、LoRA 通用开关或图层工具，除非对应功能完成并对当前创作有帮助。

## 3. 信息架构

| 一级入口 | 用户任务 | 默认内容 |
|---|---|---|
| 创作 Studio | 文生图、图像修改、文/图生视频 | 最近草稿；首次为空状态 |
| 素材库 Library | 找结果、查看原图、复用、对比、导出 | 按日期排列的本地结果，图像/视频过滤 |
| 任务 Tasks | 看本次运行、失败与历史 | 正在运行 → 最近完成；服务资源等待单独显示 |
| 模型 Models | 导入、检查、准备、加载/释放 | 已添加模型，按是否可用于当前任务排序 |
| 设置 Settings | 存储、运行、服务、外观、诊断 | 原生设置窗口，非创作大面板 |

左侧底部仅常驻“本机运行 · GPU”及可展开设备状态，避免芯片、Python、路径和四个模型灯占满首屏。加速页、缓存页、性能报告作为 Models/Settings 的详情，不增加七八个一级导航项。

首发“项目”采用轻量草稿集合：默认“未命名创作”自动保存，重命名可选。完整文件夹项目、共享、剪辑工程放后续，避免首次使用先建项目。

## 4. Studio 布局

桌面推荐 1440 × 900 pt；完整布局如下（尺寸见视觉规范）：

```text
┌ 窗口控件 / TurboCider ───── 草稿名称 · 已保存 ───── 查看器 / 参数开关 ┐
│ 导航  │ 图像 / 编辑 / 视频                      │ 生成参数           │
│       │                                       │ 模型与就绪状态     │
│ 创作  │        大媒体查看器                    │ 尺寸 / 时长        │
│ 素材  │  空态 / 最终图 / 视频 / 明确标识的预览  │ 当前模式专属输入   │
│ 任务  │                                       │ 种子 / 音频        │
│ 模型  │ 当前草稿的结果缩略条                  │ ▸ 高级设置         │
│       │ 提示词 + 有序参考素材 + 生成按钮        │ 执行方式摘要       │
│ 设置  │ 阶段 · 速度 · 已用时 · 预计剩余 · 取消 │                    │
└ 本地服务状态 ───────────────────────────────────────────────────────┘
```

### 4.1 顶部工具栏

显示草稿标题和保存状态；全局动作只有新建、导航显示/隐藏、参数检查器开关。导出属于当前结果的查看器工具栏，不与“生成”争夺视觉焦点。保存失败显示“尚未保存”及重试，不能继续给“已保存”标记。

图像/编辑/视频是任务选择器；切换时恢复对应草稿或保留兼容字段。不得默默清空提示词、首帧、参考顺序或高级值。切换模型后，将不兼容素材置于“当前模式未使用”区域；给出移除/恢复动作及参数调整差异。

### 4.2 媒体查看器

- 图片：适应窗口、100%、缩放、拖动平移；有透明度才使用淡棋盘；元信息放底部或详情。
- 编辑：原图/结果切换和 A/B 对比。对齐比较要求像素尺寸一致；不同尺寸提示“按画面适配”，不能暗示逐像素一致。
- 视频：原生播放器、播放/暂停、定位、音量/静音、实际时长与帧率；后续逐帧导航。首发仅播放轨道，不画不可用的剪辑时间线。
- 中间预览：只有引擎输出可解码资产才显示，并标“中间预览 · 非最终结果”；不以模糊上一张图冒充实时生成。没有中间预览时保留上一结果并标“上一结果”，下方显示新任务进度。
- 结果操作：保存副本、Finder 显示、复制参数、设为参考、作为视频首帧。视频入口先校验目标模型支持，再创建新草稿。
- 当前草稿结果条默认 4–8 个缩略图位，更多虚拟化滚动；点击只切换选择，不启动加载或生成。

### 4.3 提示词 Composer

固定在中间区域底部，初始 3–4 行，可展开；参考素材放其上方横排。素材缩略图标角色和顺序，例如“首帧”“参考 1”“参考 2 · 风格”。文件过多不压缩到不可辨认，改为横向滚动与计数。

首版主按钮显示“生成图像”或“生成视频”，每次一个主输出；单击后立即进入提交状态，防止重复提交。Cmd+Return 与按钮一致；中文输入法组词期间不得误提交。运行中可编辑下一份草稿，主按钮禁用并显示“正在生成”，独立提供取消；完成后手动再次生成，不提供加入队列或批量数量。

负面提示词只在 operation 声明支持时出现。未知参数不能自动加在通用输入区。长提示词显示字符数仅供编辑，模型 token 限制以 tokenizer/plan 返回为准，不静默截断。

### 4.4 参数检查器

按“模型 → 输出 → 模式专属 → 高级”排列，使用分组和留白，避免卡片套卡片。模型行同时显示名称、已检查状态与执行能力，不展示十几个技术徽章。

- 常用：分辨率预设、横竖比例、视频时长、音频（按能力）。
- 专属：FLUX 原图影响强度/参考顺序；LTX 首帧与动作变化；H3 首尾帧、参考视频音轨角色。
- 种子：常用区直接可见，默认固定 42，可输入整数、随机一次或每次随机；单次实际 seed 冻结到请求。
- 高级：允许修改的步数、精度/近似许可、引擎专属参数。固定 schedule 为说明值，不给无效滑块。
- 执行摘要：“GPU · 模型将按需加载”；已选混合路线则显示“混合加速 · 此规格已验证”或“实验”。点击进入详细计划。

多个视频模型帧数存在离散合法集合。时长滑块/输入只落在已知合法规格；规格必须来自当前运行时：兼容 LTX 推荐 704×480，而本轮原生 descriptor 为 704×448 且 executor 尚不可执行，不混用两者预设。若推荐 97 帧/24 fps，显示“约 4.04 秒 · 97 帧 · 24 fps”，不能把 704×480 标成 16:9，也不能隐式提交任意 4 秒对应的 96 帧。最终播放器时长取媒体实际元数据。

## 5. 首发模型与操作矩阵

下表“兼容”指根 README 与 model pack 的现有控制平面；“原生”指 `native/` 的新实现。发布时必须再次按 operation、权重、shape、设备与后端验证。

| 模型 | 兼容路径当前声明 | 新原生当前状态 | 首发界面与约束 |
|---|---|---|---|
| FLUX.2 Klein 4B | 文生图、img2img、有序多图编辑，最多 8 参考 | 已有 BF16 文生图和 transform/edit 代码；按操作验收 | 图像/编辑；编辑以 operation 验收为门槛；多图编辑不能沿用标准混合路线 |
| LTX-2.5 Distilled | 文生视频、单首帧图生视频，音视频输出 | 数学 executor 待完成 | 文/图生视频；兼容推荐 704×480；当前原生描述 704×448、执行待完成；97 帧、24 fps，8+3 步分阶段展示 |
| MiniMax H3 Turbo | 文本、首尾帧、图像/视频/音频参考 | 已有 executor 入口，weight_validation=pending | 首尾帧与 reference 分模式且互斥；4 步、24 fps；形状及输入仍需计划和媒体验收 |
| FastMetal 1.3B QAD | 视频、固定 3 步、16 fps、无音频 | 不作为此次三模型原生承诺 | 保留可扩展注册入口；不是首发首页主推任务 |

首发完整版本的含义：至少完成前三个模型的已承诺 operation 和媒体验收。若 H3/LTX 未就绪，只能发布明确标识的 FLUX 预览版，或清晰标识使用兼容运行时；不能靠展示可点击的卡片宣称完整原生支持。

未来能力：mask 局部重绘、区域生成、LoRA、视频延长/重拍/多关键帧、音频独立创作、批量探索。保留 operation schema 与资产关系扩展点，首发不显示未实现工具或无效开关。

## 6. 关键用户旅程

### A. 首次出图

启动 → 检查服务和可用模型 → 无模型时显示“导入本地模型”与可选“获取模型” → 校验组件/版本/空间 → 返回原草稿 → 写提示词 → 查看输出规格与按需加载提示 → 生成 → 原地出现结果 → 保存或继续修改。

导入失败定位到缺失组件，并保留已选文件夹。无需用户先理解 Core ML 编译。下载必须由用户主动发起，显示来源、固定版本、下载/临时/最终空间和位置；默认先走可运行 GPU。

### B. 图像修改并转视频

素材库选图 → “编辑此图”创建带来源的草稿 → 原图或多参考模式 → 修改提示词/强度 → 对比 → “作为视频首帧” → 切到 LTX 或支持首帧的 H3 → 校验输入与规格 → 生成视频 → 在同一素材关系中保存图像与视频。各阶段保留源资产 ID，不依赖文件名推断版本。

首发对 img2img 强度使用模型定义的说明；不能假设 LTX 的 strength 与 FLUX 的数值方向完全一样。UI 映射必须有端点测试与 operation 文案。

### C. 模型加载与切换

进入 Models → 选择“已校验”的模型 → 展开组件与可运行操作 → 可点“加载到内存”；生成时也可自动加载。正在用的模型显示被哪个任务占用。“卸载”应标为“释放内存”，与“移除登记”“删除模型文件”分离。

切换模型保留当前任务的模型引用；下一任务需要资源时排队释放/加载。没有可靠内存估计则显示“尚无法估计”，不能根据权重文件大小宣称一定装得下。GPU 可运行但缺 ANE 文件时提示“GPU 就绪 · 混合加速未准备”，不标整模型不可用。

### D. 长视频等待与失败恢复

用户生成后可离开 Studio 浏览素材；任务入口显示计数。切回时恢复任务快照。断连显示“连接中断 · 正在重新连接”，保留最后真实状态及采样时间。取消显示“正在安全停止”，收到终态才解除占用。失败保留提示词和输入，提供调整规格/重新定位模型/查看详细原因；重试新建任务，不覆盖旧失败记录。

App 退出行为必须与实际运行方式一致：当前嵌入原生运行中退出会中断，退出时明确说明；只有独立服务与恢复机制验收后才能提供“退出 App 后继续生成”。重启恢复记录不等于从上次 denoise 步断点续推。

## 7. 任务、素材与模型页面

### Tasks

紧凑列表行：缩略图/类型、提示词摘要、模型、阶段、进度、速度、已用时/ETA。正在运行固定顶部；首版无 App 队列编辑，服务资源等待可查看原因。队列管理与重排放首发之后。详情含不可变参数、实际执行计划、阶段耗时、错误、输出与复制诊断。首发支持查看、取消、复用参数；暂停/恢复不可用时不显示。

### Library

可调整缩略图大小的结果网格，默认按日期；过滤图像/视频、模型、收藏。每张图显示必要信息，悬停补充但关键动作键盘可达。首发可从任务产物建立轻量索引；完整导入素材索引、标签和多选批量导出逐步补齐。

删除设计分离“从库中移除”和“移到废纸篓”；原始输入、受管副本、输出各有所有权。外部卷断开显示离线并允许重新定位，不删记录。运行任务或草稿引用的素材不得被自动清理。

### Models

优先列表/紧凑卡片，列出模型名、支持操作、磁盘状态、会话状态与大小；只有选中详情才展开组件、精度、版本、兼容格式、加速范围。

磁盘状态：未添加 → 检查中 → 缺组件 / 已校验 / 不兼容 / 离线。

准备任务：等待 → 下载 → 转换 → 编译 → 验证 → 完成 / 失败 / 取消。

会话状态：未加载 → 加载中 → 可复用 → 使用中 → 释放中 → 未加载；失败单独标识。准备与会话不是互斥的一条进度条。

“Load 模型”仅对引擎可加载的目录/格式有效；导入任意 safetensors 文件不代表新增任意架构。首发支持已注册模型，后续通过 ModelModule 扩展。

## 8. 实时性能的产品展示

默认一行：`细化 2 / 3 · 1.24 秒/步 · 已用 18 秒 · 预计还需 7–11 秒`。该文字仅示例，数值不是实测。

- 真实采样步速与阶段名称一起显示；LTX 基础生成与细化分别统计，不能把 11 步均分总时长。
- 图像生成可显示“秒/张”（完成后）；视频播放参数显示“24 fps”，生成性能明确显示“生成吞吐：x 帧/秒”且只在可定义测量窗口时显示。
- 常驻信息最多四项，资源信息点开后出现：进程内存、系统内存压力、当前执行计划、模型是否复用。没有采样显示“未提供”，不是 0。
- “GPU + ANE”标签表达所选计划；只有运行时观测证据充分才说实际 ANE 执行，不能凭配置开关显示 100% ANE 使用率。
- ETA 是估计且可变，未有足够样本显示“估算中”；无总体计划权重只显示阶段进度，不伪造全程百分比。
- 详细性能页区分排队、下载/编译、模型加载、编码、采样、解码、导出及总墙钟；可并行的阶段不能简单相加。

具体字段、公式、采样与降级规则见实现方案。

## 9. 非目标与成功标准

首发不做批量生成、自动连续生成、App 队列编辑、节点编辑器、完整 NLE 视频剪辑、多模型并行大负载、任意模型自动适配、社区商城、自动上传素材或跨设备协作。

产品验收目标（待测试的目标，非已达成数据）：

1. 已有可用模型时，新用户在 3 个核心动作内提交默认图像请求：选择创作类型、输入提示词、生成。
2. 1280×800 下不滚动即可看到媒体、提示词、主操作、当前阶段与时间；次要参数可在检查器内滚动。
3. 用户能正确解释已下载/已加载/使用中，以及视频 fps/生成速度的差别。
4. 完成图像 → 编辑 → 首帧视频流程不需要 Finder 中转。
5. 所有不可用入口给出准确原因；长任务、失败、断连和重启不丢草稿与已提交记录。
6. 性能展示不会触发额外模型解码或 GPU 同步，也不掩盖原生迁移未完成的范围。
