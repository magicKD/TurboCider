## 三臂和计时边界

A：MLX eager `X @ W.T`，B：原生 `MPSMatrixMultiplication` 的同一数学运算，C：`mx.compile` 包装的单个 GEMM。每 block 顺序 A/B/C/C/B/A，8 个 block；每臂第一次调用单列，各 3 次预热。每个正式输出完整对 CPU FP64 `einsum(optimize=False)` 检查，读回/metrics 在正式 timer 外；没有 BLAS oracle 警告。

三臂的 Python call→output-ready wall 包含各自编码、提交与完成等待。B 经 ctypes 进入同进程 dylib，无跨进程 RPC；另保存 C++ 内部 wall 与完成后的 command-buffer GPU timestamp。**没有 MLX 的对应 GPU timestamp**，所以不能把不同 wall 全部归因于 shader 或算术吞吐。

所有输入先准备到各臂 device-accessible storage；CPU 生成、row padding/upload、MPS 对象/queue/descriptor 创建、动态库编译与 oracle 在热态计时外。MPS 长期复用 output buffer，MLX 保持其自身输出分配行为；这是各路线的 resident API 成本，不是强制同一 allocator 的 kernel-only 对决。

## 正确性、尾部和物理 rowBytes

Python 生成同一 X/W 的实际 FP32/FP16 值，分别给 native 和 MLX；CPU FP64 只解释这些源值，不用另一臂输出作 oracle。FP32 relative L2 预设 ≤3e-5、FP16 ≤0.003；正式样本最大 relative L2 约 2.154e-4。全部样本 finite、shape 和完整元素检查通过，不代表任意输入范围或模型画质通过。

MPS 使用 `rowBytesFromColumns:dataType:` 的 row pitch，创建 X[M,K]、W[N,K]，右操作数转置；Python 读 shared output 时显式传真实 byte stride。33×529×1007 case 专门覆盖非整除维度，未把错读的连续 buffer 当结果。它验证 MPSMatrix 路线，**不是低比特 MTLTensor ABI 验证**。

输出只在 command buffer 完成后读取；owner 保留 matrices、operation、buffers、queue，完成后才销毁。所有外层读取在下一次覆盖复用输出之前完成。此 ABI 仅用于单线程研究，不是通用跨线程/异步内存接口。

## 这次实验对设计有什么帮助

前轮 [RMS-chain 编译](../../MAINTENANCE.md)的收益不能机械迁到一个已经独立完成的 GEMM；减少 elementwise dispatch/中间写回与给单 op 加 compile wrapper 是不同候选。原生 MPS 也不是“去掉 Python 就自动更快”：这里 Python 边界已匹配，内部实现、准备/分配和提交策略仍不同。

第一份 7×13×19、2-block smoke 的 FP16 timing 波动很大，故只列功能 smoke，不进入正式表；smoke hash 与范围单列。正式两进程的全部 order-sensitive 结果保留。未测 cold model、功耗、隔离峰值、GPU counter、完整 FFN/block/request，也没有采用生产默认。

CLI 会编译独立 dylib 到临时目录，记录源码、实际库/wheel、输入/权重和 raw-report hashes，拒绝已有报告；temporary library 自动回收，整理后的 capsule 包含全部样本。普通 unittest 只验证 ABCCBA/负控，不静默启动 GPU。
