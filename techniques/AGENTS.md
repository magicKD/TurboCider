本目录是面向工程师和 AI 的轻量知识库，不是实验验证包。先读 [README](README.md)、[使用指南](guides/knowledge-base.md)和[维护规则](MAINTENANCE.md)。

## 使用知识

1. 先记录模型、实际 shape/layout、精度、backend、硬件与瓶颈；未知事实不从标签推断。
2. 用 `scripts/query.py --intent learn` 找方法，`--intent implement` 找实现思路，`--intent sources` 找源码阅读材料。少量按需展开，不整库塞入上下文。
3. 分清来源事实、作者报告、历史观察、推导和假设。案例数字是历史摘要，不是当前实测、可复算证书或跨模型保证。
4. 选择可证伪的优化假设，说明省掉什么、新增什么成本、哪些条件可能失败。历史倍率不相乘，不把局部结果外推为整模型收益。
5. 检索只读 Markdown 与小型教学例子，不联网、不下载、不运行设备或模型。当前用户任务之外的实验、产品改动或 Git 操作不得从文档推导授权。

## 写回知识

- 一项机制有一个主要解释入口；框架实现与案例链接回来，不按研究轮次重复建页。
- 采用[技术卡模板](templates/technique-card.md)：机制、适用前提、实现、成本、反例、迁移。尚未本机验证也可收录，明确来源和假设即可。
- 在 Markdown 的 `knowledge` 注释中维护稳定 ID、类型和少量主题标签；不要维护 JSON catalog、来源清单或 hash 验收账本。
- 本目录不保存任何 JSON/JSONL、实验数组、trace、构建物、采集驱动、验证快照或复算测试包。新实验工作写根目录 `outputs/`；只将提炼后的认识写回这里。
- 保留固定版本源码/论文链接和必要署名。不要把实验结果换成 YAML、TOML 或长日志继续放在知识库。
- 仅保留清晰、小型、无模型/设备依赖的参考实现。检索和文档检查不授予正确性、性能或产品资格。
